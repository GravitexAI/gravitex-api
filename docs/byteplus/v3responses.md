thinking.**type ** `string` <span data-api-tag="require|JOQAj6">必选</span>

One of `enabled`, `disabled`, or `auto`.


* `enabled`: The deep\-thinking mode is enabled. The model always performs additional reasoning before responding.

**reasoning** `object` `Default: {"effort": "medium"}`

Limit the workload of deep thinking. Reducing the depth of deep thinking results in faster response times and lower token consumption for deep thinking.


Attributes


reasoning.effort `string`

> See [Control deep reasoning](https://docs.byteplus.com/en/docs/ModelArk/1956279#controlling-deep-reasoning) for models that support this field.


Valid values:


   * **minimal**: Disable thinking and answer directly.

   * **low**: Lightweight thinking, prioritizing fast responses.

   * **medium**: Balanced mode, considering both speed and depth.

   * **high**: Deep analysis for handling complex problems.


Notes for `thinking.type` and `reasoning.effort`:


* When `thinking.type` is set to **enabled**: You can configure `reasoning.effort`. If `reasoning.effort` is set to **minimal**, thinking is disabled and the model answers directly.

* When `thinking.type` is set to **disabled**: `reasoning.effort` only supports **minimal**. Setting it to low, medium, or high will result in a request error.

**temperature** `float / null` `Default: 1`

Value range: `[0, 2]`.

The temperature of sampling. Controls the variability and randomness of generated text. If the value is set to 0, the model only considers the token with the highest logprob.

Higher values (for example, 0.8) make the output more random; Lower values (for example, 0.2) make the output more deterministic.

It is recommended that you adjust either `temperature` or `top_p` , not both.


---



**top_p** `float / null` `Default: 0.7`

Valid range: `[0, 1]`.

The probability threshold for nucleus sampling. If the value is set to 0, the model deterministically selects the highest\-logprob token. Higher values increase randomness/diversity; lower values increase determinism/focus.

For example, with `top_p`  = 0.1, only tokens within the top 10% cumulative probability mass are considered.

It is recommended that you adjust either `temperature` or `top_p` , not both.
