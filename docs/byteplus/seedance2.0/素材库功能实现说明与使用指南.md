# Seedance 素材库功能 — 实现说明 & 使用指南

---

## 一、功能是什么

**素材库**让用户在生成视频前，先上传人像照片（素材），然后在视频生成时引用这些素材，实现**人脸一致性**（同一个角色在多个视频中保持一样的脸）。

简单说：先传照片 → 拿到素材 ID → 生成视频时带上这个 ID。

---

## 二、两种模式

系统支持两种素材库后端，取决于渠道配置：

| | Uptoken 模式 | BytePlus 模式 |
|---|---|---|
| 上传方式 | 直接上传文件（multipart） | 先传 OSS 拿到 URL，再通过 URL 创建素材 |
| 素材组 | 没有素材组概念，素材是扁平的 | **有素材组，素材必须归属到某个组** |
| 适用渠道 | type=59（Uptoken 渠道） | type=54（豆包视频渠道），需配置 AK/SK |
| 认证 | 走渠道的 Bearer Token | 走 AK/SK（BytePlus SDK） |

**两种模式互不冲突**，可以同时存在。用户如果同时有两种渠道，系统会自动识别。

> **重要**：BytePlus 模式下，添加素材时 `group_id` 是**必填**的。用户必须先创建素材组，再往组里添加素材。不能脱离素材组单独创建素材。

---

## 三、BytePlus 模式的完整流程

```
1. 用户先创建一个素材组（POST /v1/asset-groups）
    ↓
2. 用户上传文件到前端
    ↓
3. 前端上传到 OSS（拿到公网 URL）
    ↓
4. 调用 POST /v1/assets（JSON body: url + group_id）
    ↓
5. 网关 → BytePlus SDK CreateAsset
    ↓
6. BytePlus 异步处理素材（Processing → Active）
    ↓
7. 用户轮询查看状态，等变成 Active
    ↓
8. 用户在视频生成时引用 asset://xxx
    ↓
9. 网关识别 asset:// 前缀 → 路由到对应渠道
    ↓
10. 上游收到 asset://xxx 引用 → 生成视频
```

## 四、用户使用方式

### 方式 1：客户端 UI（前端页面）

1. 打开素材库页面
2. 如果是 BytePlus 模式：
   - 先创建一个素材组（如"角色A"）
   - 点击上传图片 → 系统自动上传到 OSS → 创建素材
   - 等待状态变为 `Active`
   - 在视频生成时选择要引用的素材
3. 如果是 Uptoken 模式：
   - 直接上传图片
   - 等待状态变为 `Active`
   - 在视频生成时选择要引用的素材

### 方式 2：API 调用（完整样例）

以下是用户通过 API 使用素材库的**完整流程**，按顺序执行。

所有接口的 Base URL 前缀为 `/llm-api`（即实际请求路径为 `https://your-domain.com/llm-api/v1/...`）。

---

#### 步骤 1：创建素材组（仅 BytePlus 模式需要）

```bash
curl -X POST https://your-domain.com/llm-api/v1/asset-groups \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "角色A",
    "description": "女主角参考照片"
  }'
```

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 素材组名称 |
| description | string | 否 | 描述 |
| channel_id | int | 否 | 指定渠道，不传则自动选择第一个可用的 BytePlus 渠道 |

**响应**：
```json
{
  "group_id": "group-20260416abcdef",
  "name": "角色A",
  "description": "女主角参考照片",
  "channel_id": 123
}
```

> 记住返回的 `group_id`，后续创建素材时需要用到。

---

#### 步骤 2：查看素材组列表

```bash
curl https://your-domain.com/llm-api/v1/asset-groups \
  -H "Authorization: Bearer sk-xxx"
```

**响应**：
```json
{
  "groups": [
    {
      "id": 1,
      "group_id": "group-20260416abcdef",
      "name": "角色A",
      "description": "女主角参考照片",
      "space_label": "A",
      "asset_count": 3,
      "created_at": 1713254400,
      "updated_at": 1713254400
    }
  ],
  "total": 1,
  "has_byteplus_channels": true
}
```

---

#### 步骤 3：添加素材到素材组

**BytePlus 模式**（JSON，URL 方式）：

```bash
curl -X POST https://your-domain.com/llm-api/v1/assets \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-oss-bucket.oss-cn-hangzhou.aliyuncs.com/face.jpg",
    "group_id": "group-20260416abcdef",
    "asset_type": "Image",
    "name": "正面照"
  }'
```

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| url | string | 是 | 素材的公网可访问 URL（如 OSS 链接） |
| group_id | string | **是** | 素材组 ID（必须是自己创建的组） |
| asset_type | string | 否 | 素材类型，默认 `Image`，可选 `Video`、`Audio` |
| name | string | 否 | 素材名称 |

**响应**：
```json
{
  "virtual_id": "asset-20260416xyz",
  "asset_url": "asset://asset-20260416xyz",
  "group_id": "group-20260416abcdef",
  "status": "pending"
}
```

> `status` 初始为 `pending`（处理中），需要等变成 `active` 才能在视频生成中使用。

**Uptoken 模式**（multipart 文件上传）：

```bash
curl -X POST https://your-domain.com/llm-api/v1/assets \
  -H "Authorization: Bearer sk-xxx" \
  -F "file=@face.jpg"
```

> Uptoken 模式不需要 group_id，直接上传文件即可。

---

#### 步骤 4：查看素材状态（等待处理完成）

```bash
curl https://your-domain.com/llm-api/v1/assets/asset-20260416xyz \
  -H "Authorization: Bearer sk-xxx"
```

**响应**（BytePlus 模式）：
```json
{
  "virtual_id": "asset-20260416xyz",
  "asset_url": "asset://asset-20260416xyz",
  "url": "https://cdn.byteplus.com/signed-url/...",
  "filename": "正面照",
  "status": "active",
  "group_id": "group-20260416abcdef",
  "byteplus_status": "Active",
  "asset_type": "Image",
  "created_at": 1713254400
}
```

> `status` 变为 `active` 后即可使用。如果是 `failed` 则素材处理失败，需要重新上传。

```bash
# 按素材组过滤（BytePlus）
curl "https://your-domain.com/llm-api/v1/assets?group_id=group-20260416abcdef" \

```

**响应**：
```json
{
  "assets": [
    {
      "virtual_id": "asset-20260416xyz",
      "asset_url": "asset://asset-20260416xyz",
      "url": "https://cdn.byteplus.com/signed-url/...",
      "filename": "正面照",
      "status": "active",
      "group_id": "group-20260416abcdef",
      "space_label": "A",
      "created_at": 1713254400
```

#### 步骤 6：在视频生成中引用素材

素材状态为 `active` 后，在视频生成请求的 `content` 中用 `asset://` 前缀引用：

**引用图片素材**：
```bash
curl -X POST https://your-domain.com/llm-api/v1/video/generations \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2-0-v2p0",
    "content": [
      {"type": "image_url", "image_url": {"url": "asset://asset-20260416xyz"}},
      {"type": "text", "text": "一个女孩在花园里跳舞"}
    ]
  }'
```

**引用多个图片素材**（多模态参考，Seedance 2.0 最多 9 张）：
```bash
curl -X POST https://your-domain.com/llm-api/v1/video/generations \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2-0-v2p0",
    "content": [
      {"type": "image_url", "image_url": {"url": "asset://asset-face-front"}},
      {"type": "image_url", "image_url": {"url": "asset://asset-face-side"}},
      {"type": "image_url", "image_url": {"url": "asset://asset-full-body"}},
      {"type": "text", "text": "一个女孩在花园里跳舞，保持人物一致性"}
    ]
  }'
```

**引用视频素材**：
```bash
curl -X POST https://your-domain.com/llm-api/v1/video/generations \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2-0-v2p0",
    "content": [
      {"type": "video_url", "video_url": {"url": "asset://asset-video-ref"}},
      {"type": "text", "text": "参考这个视频的动作风格"}
    ]
  }'
```

**引用音频素材**：
```bash
curl -X POST https://your-domain.com/llm-api/v1/video/generations \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2-0-v2p0",
    "content": [
      {"type": "image_url", "image_url": {"url": "asset://asset-face-front"}},
      {"type": "audio_url", "audio_url": {"url": "asset://asset-bgm"}},
      {"type": "text", "text": "一个女孩随着音乐跳舞"}
    ]
  }'
```

> **注意**：同一请求中引用的所有素材必须来自同一个渠道（channel），否则会报错。一般来说同一用户的素材都在同一个渠道，不需要担心。

---

#### 步骤 7：删除素材

```bash
curl -X DELETE https://your-domain.com/llm-api/v1/assets/asset-20260416xyz \
  -H "Authorization: Bearer sk-xxx"
```

**响应**：
```json
{
  "deleted": true,
  "virtual_id": "asset-20260416xyz"
}
```

---

#### 步骤 8：删除素材组（级联删除组内所有素材）

```bash
curl -X DELETE https://your-domain.com/llm-api/v1/asset-groups/group-20260416abcdef \
  -H "Authorization: Bearer sk-xxx"
```

**响应**：
```json
{
  "deleted": true,
  "group_id": "group-20260416abcdef"
}
```

> **注意**：删除素材组会同时删除组内所有素材，操作不可恢复。

## 五、关键设计逻辑

### 1. 为什么需要两种模式？

- Uptoken 是旧的素材库方案，简单但功能有限
- BytePlus 是火山官方 SDK 方案，支持素材组管理，是未来方向
- 保留 Uptoken 是为了向后兼容，已有用户不受影响

### 2. BytePlus 模式下素材必须归属素材组

后端代码中 `group_id` 字段标记为 `binding:"required"`，即 BytePlus 模式下创建素材时**必须指定 group_id**。

原因：
- 火山官方 API（`CreateAsset`）要求 `GroupId` 参数
- 素材组是火山资源管理的基本单位，不支持脱离组创建素材
- 便于用户按角色/场景分类管理素材

**用户操作顺序**：先建组 → 再往组里加素材。不能跳过建组直接加素材。

### 3. 渠道路由怎么工作？

视频生成请求中带了 `asset://xxx` 引用时：
1. `AssetResolveChannel` 中间件扫描请求体中的 `image_url`、`video_url`、`audio_url` 字段
2. 提取所有 `asset://` 前缀的引用
3. 通过素材 ID 查到它属于哪个渠道
4. 校验所有素材属于同一个渠道
5. 强制将请求路由到该渠道
6. **同一请求中的所有素材必须来自同一个渠道**（否则报错）

### 4. 状态流转

```
创建素材 → pending（处理中）→ active（可用）
                             → failed（失败）
```

前端会轮询刷新状态。BytePlus 通过 SDK 查，Uptoken 通过 REST 查。

### 5. Space Label（空间标签）

- 同一用户可能通过不同渠道（不同 AK/SK 账号）创建素材
- 前端用 A、B、C 标签区分不同"空间"
- 不暴露实际的 channel_id 给用户

## 六、API 路由总览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/assets` | 创建素材（multipart=Uptoken，JSON=BytePlus） |
| GET | `/v1/assets` | 列出素材（支持 `?group_id=xxx` 过滤） |
| GET | `/v1/assets/:virtual_id` | 查看单个素材（刷新状态） |
| DELETE | `/v1/assets/:virtual_id` | 删除素材 |
| POST | `/v1/asset-groups` | 创建素材组（仅 BytePlus） |
| GET | `/v1/asset-groups` | 列出素材组 |
| DELETE | `/v1/asset-groups/:group_id` | 删除素材组（级联删除组内素材） |

## 七、管理员配置

在管理后台编辑**豆包视频渠道（type=54）**时，可以看到"BytePlus 素材库配置"区域：

- Access Key（AK）
- Secret Key（SK）
- Region（默认 `ap-southeast-1`）
- Project Name（默认 `default`）

配置了 AK/SK 的渠道才会启用 BytePlus 素材库模式。没配的继续走 Uptoken。

## 八、常见问题

**Q: Uptoken 用户会受影响吗？**
A: 不会。没有 BytePlus AK/SK 配置的渠道继续走 Uptoken 流程，完全不变。

**Q: 能否同时有 Uptoken 和 BytePlus 素材？**
A: 可以。不同渠道独立运作。但同一个视频生成请求中，引用的素材必须来自同一个渠道。

**Q: BytePlus 素材为什么不能直接上传文件？**
A: 火山官方 API 只接受公网可访问的 URL，不支持文件上传。所以需要先传到 OSS 拿到 URL。前端已经自动处理了这一步（用户选择文件 → 自动上传 OSS → 自动创建素材）。

**Q: BytePlus 模式下能不能不建素材组直接上传素材？**
A: **不能**。`group_id` 是必填参数，火山官方 API 也要求素材必须归属到一个 AssetGroup。用户必须先创建素材组，再往里面添加素材。

**Q: 素材组有什么用？**
A: 管理用。比如把"角色A"的所有参考照片放一个组，"角色B"放另一个组。方便查找和管理。在生成视频时，可以跨组引用素材（只要在同一渠道下）。

**Q: 每个用户能创建多少个素材组？**
A: 网关限制每用户每渠道 5 个（防御性限制）。火山官方的上限未知，已列入待确认清单。

**Q: 删除素材组会怎样？**
A: 会同时删除组内所有素材，操作不可恢复。先删上游（火山），再删本地。

**Q: 素材创建后多久能用？**
A: 火山异步处理，没有明确 SLA。需要轮询 `GET /v1/assets/:virtual_id` 查状态，等 `status` 变为 `active` 后即可使用。
