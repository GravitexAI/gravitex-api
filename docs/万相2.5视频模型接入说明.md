# 万相 2.5 视频模型接入说明

本文档以当前线上实际可用调用格式为准，适用于：

- `wan2.5-i2v-preview`
- `wan2.5-t2v-preview`

重点说明本项目网关的真实请求结构、响应结构和查询方式。

## 1. 接口地址

### 1.1 提交任务

```text
POST https://api.gravitex.ai/v1/video/generations
```

### 1.2 查询任务

```text
GET https://maas.gravitex.ai/llm-api/v1/video/generations/{task_id}
```

## 2. 鉴权方式

```http
Authorization: Bearer sk-xxxx
```

## 3. 当前线上可用的传参方式

结合你的实测结果，当前推荐格式不是直接传顶层 `input_reference` / `resolution`，而是传：

- 顶层基础字段
- `metadata.input`
- `metadata.parameters`

也就是说，请求体建议按“接近阿里原生结构”的方式组织，再由网关转发和落库。

## 4. `wan2.5-i2v-preview` 请求格式

### 4.1 推荐请求示例

```json
{
  "model": "wan2.5-i2v-preview",
  "prompt": "生成吃草小羊\n",
  "duration": 10,
  "metadata": {
    "input": {
      "img_url": "http://gravitexgrayoss.tos-s3-accelerate.bytepluses.com.cn/2026/06/18/e6d4d8b959f847c88b8fcea36508fd6f.png",
      "prompt": "生成吃草小羊\n",
      "media": [
        {
          "type": "reference_image"
        }
      ]
    },
    "parameters": {
      "resolution": "480P",
      "duration": 3,
      "prompt_extend": true,
      "watermark": false,
      "ratio": "16:9"
    }
  }
}
```

### 4.2 字段说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `model` | 是 | 固定传 `wan2.5-i2v-preview` |
| `prompt` | 建议传 | 顶层提示词，建议与 `metadata.input.prompt` 保持一致 |
| `duration` | 可传 | 顶层时长。若同时传 `metadata.parameters.duration`，实际以更内层业务参数为准 |
| `metadata.input.img_url` | 是 | 首帧图片地址 |
| `metadata.input.prompt` | 建议传 | 上游实际生成使用的 prompt，建议与顶层 `prompt` 一致 |
| `metadata.input.media` | 可选 | 当前实测可传 `reference_image` 描述输入媒体类型 |
| `metadata.parameters.resolution` | 建议传 | `480P` / `720P` / `1080P` |
| `metadata.parameters.duration` | 建议传 | 实际希望生成的视频时长 |
| `metadata.parameters.prompt_extend` | 可选 | 是否开启提示词扩写 |
| `metadata.parameters.watermark` | 可选 | 是否加水印 |
| `metadata.parameters.ratio` | 可选 | 比例，例如 `16:9` |

## 5. 参数优先级说明

从你的实测结果看，顶层字段和 `metadata.parameters` 同时存在时，要以 `metadata.parameters` 中的最终值理解结果。

你的示例中：

- 顶层 `duration` 是 `10`
- `metadata.parameters.duration` 是 `3`
- 最终查询返回 `seconds` 为 `"3"`
- `usage.duration` 为 `3`

这说明当前实际生效的是：

```text
metadata.parameters.duration = 3
```

因此建议：

- 顶层字段用于兼容或摘要展示
- 真正的模型参数统一放在 `metadata.parameters`

## 6. 提交任务响应格式

当前提交接口返回的是 OpenAI Video 风格对象，不是传统的 `{code,data}` 包装。

示例：

```json
{
  "id": "d09ee9f4-04ba-4c3f-bc1b-974cb19e109f",
  "object": "video",
  "model": "wan2.5-i2v-preview",
  "status": "queued",
  "progress": 0,
  "created_at": 1781767983,
  "metadata": {
    "output": {
      "task_id": "d09ee9f4-04ba-4c3f-bc1b-974cb19e109f",
      "task_status": "PENDING"
    },
    "request_id": "2a17a551-0db2-910d-988b-7d5abed99d2d"
  }
}
```

### 6.1 关键字段

| 字段 | 说明 |
| --- | --- |
| `id` | 本项目任务 ID，后续查询直接用它 |
| `object` | 固定为 `video` |
| `model` | 使用的模型 |
| `status` | 当前任务状态，初始一般为 `queued` |
| `progress` | 当前进度 |
| `created_at` | 创建时间戳 |
| `metadata.output.task_id` | 上游任务 ID，通常与 `id` 一致 |
| `metadata.output.task_status` | 上游状态，如 `PENDING` |
| `metadata.request_id` | 本次提交请求的 request_id |

## 8. 查询结果字段说明

### 8.1 顶层 `data`

| 字段 | 说明 |
| --- | --- |
| `id` | 任务 ID |
| `object` | 固定为 `video` |
| `model` | 模型名 |
| `status` | 统一状态，如 `completed` |
| `progress` | 进度，完成后一般是 `100` |
| `created_at` | 创建时间 |
| `completed_at` | 完成时间 |
| `seconds` | 最终视频秒数，字符串形式 |
| `url` | 视频地址 |
| `video_url` | 视频地址，兼容字段 |

### 8.2 `data.metadata.output`

这里保留了上游原始任务结果：

| 字段 | 说明 |
| --- | --- |
| `task_id` | 上游任务 ID |
| `task_status` | 上游状态，如 `SUCCEEDED` |
| `submit_time` | 提交时间 |
| `scheduled_time` | 调度时间 |
| `end_time` | 完成时间 |
| `orig_prompt` | 上游收到的原始 prompt |
| `video_url` | 上游返回的视频地址 |

### 8.3 `data.metadata.usage`

| 字段 | 说明 |
| --- | --- |
| `SR` | 分辨率档位，例如 `480` |
| `duration` | 最终计费/产出时长 |
| `video_count` | 生成视频数量，通常为 `1` |

## 9. 状态映射

当前项目会将上游状态转成统一状态：

| 上游状态 | 查询接口中的 `status` |
| --- | --- |
| `PENDING` | `queued` |
| `RUNNING` | `in_progress` |
| `SUCCEEDED` | `completed` |
| `FAILED` / `CANCELED` / `UNKNOWN` | `failed` |

## 10. 最推荐的接入约定

基于你给出的真实样例，建议内部统一按下面格式调用 `wan2.5-i2v-preview`：

```json
{
  "model": "wan2.5-i2v-preview",
  "prompt": "你的提示词",
  "metadata": {
    "input": {
      "img_url": "https://your-image-url",
      "prompt": "你的提示词",
      "media": [
        {
          "type": "reference_image"
        }
      ]
    },
    "parameters": {
      "resolution": "480P",
      "duration": 5,
      "prompt_extend": true,
      "watermark": false,
      "ratio": "16:9"
    }
  }
}
```

这样有几个好处：

- 与当前线上成功样例完全一致
- 参数语义最清晰
- 查询结果中的 `orig_prompt`、`usage.duration`、`SR` 更容易对齐
- 后续扩展 `wan2.5-t2v-preview`、`wan2.6`、`wan2.7` 也更自然

## 11. 实际接入注意事项

### 11.1 顶层 `duration` 不要和 `metadata.parameters.duration` 打架

如果两边不一致，容易产生理解偏差。建议正式接入时：

- 要么不传顶层 `duration`
- 要么保证它与 `metadata.parameters.duration` 完全一致

### 11.2 prompt 最好顶层和 `metadata.input.prompt` 同步

你给的实测里两边 prompt 相同，这是对的，建议保持一致。

### 11.3 `video_url` 是临时链接

查询成功后拿到的 `video_url` 一般是临时 OSS 链接，建议及时下载或转存。

### 11.4 成功判断建议以这几个字段为准

建议业务侧按以下优先级判断任务成功：

1. `data.status == "completed"`
2. `data.video_url` 或 `data.url` 非空
3. `data.metadata.output.task_status == "SUCCEEDED"`

## 12. 文生视频补充建议

虽然你这次提供的是 `wan2.5-i2v-preview` 的真实样例，但 `wan2.5-t2v-preview` 也建议沿用同一风格：

- 顶层放 `model`、`prompt`
- `metadata.input` 放 prompt
- `metadata.parameters` 放 `size` / `resolution` / `duration` / `watermark` 等参数
