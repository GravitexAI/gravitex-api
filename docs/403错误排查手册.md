# 403 错误排查手册

> 面向排查用户投诉「接口返回 403」的运维/开发指南
> 覆盖 Go 后端 (gravitex-api) 所有 `http.StatusForbidden` 触发点及日志定位方法

---

## 一、快速定位流程（三步走）

```
用户报 403
  ↓
① 问用户要 3 样东西：
   - 响应 body 里的 message 字段（最重要！）
   - 响应 Header 的 X-Oneapi-Request-Id
   - 请求的 model 名 + 大概时间
  ↓
② 按 message 关键词反查（见「常见 403 场景一览表」）
  ↓
③ 30 秒内定位到具体触发点
```

**如果只拿到用户 ID**：直接跳到「四、日志检索命令」用 user_id 反查。

## 二、用户最可能遇到的 403 场景（按频率排序）

### 🥇 TOP 1：令牌无权访问该 model（最高频）

- **触发条件**：用户配置了「令牌模型白名单」，但请求的 model 不在白名单里
- **代码位置**：`middleware/distributor.go:78`
- **日志关键词**：`no access to model`
- **响应示例**：`This token has no access to model gpt-4o`
- **解决方式**：让用户在令牌管理页勾选对应模型，或使用无白名单限制的令牌

### 🥈 TOP 2：用户余额不足

- **触发条件**：预扣费金额 > 用户剩余额度
- **代码位置**：`service/pre_consume_quota.go:39/42`
- **日志关键词**：`insufficient` / `quota` / `用户额度不足`
- **响应示例**：`用户额度不足, 剩余额度: $0.001`
- **⚠️ 特殊**：**此类 403 不写 SysLog**（`ErrOptionWithNoRecordErrorLog`），只落数据库 `logs` 表 type=5
- **解决方式**：让用户充值或联系管理员发放额度

### 🥉 TOP 3：用户被封禁

- **触发条件**：`user.status != Enabled`
- **代码位置**：`middleware/auth.go:323 / 438`
- **日志关键词**：`has been banned`
- **响应示例**：`User has been banned`
- **解决方式**：管理员后台解封用户

### 4. 订阅额度不足或未配置订阅

- **代码位置**：`service/billing_session.go:222`
- **日志关键词**：`订阅额度不足或未配置订阅`
- **解决方式**：为用户配置订阅计划或引导充值

### 5. 令牌 IP 白名单不匹配

- **触发条件**：令牌开启了 IP 白名单，但客户端 IP 不在允许列表
- **代码位置**：`middleware/auth.go:423`
- **日志关键词**：`not in the list of allowed IPs`
- **响应示例**：`Your IP is not in the list of allowed IPs for this token`
- **解决方式**：让用户在令牌设置里添加当前 IP

### 6. 渠道被禁用

- **触发条件**：请求指定的 channel 已被管理员禁用
- **代码位置**：`middleware/distributor.go:53`
- **日志关键词**：`channel has been disabled`
- **解决方式**：管理员启用渠道，或用户改用其他渠道

### 7. 令牌模型白名单为空

- **触发条件**：令牌开启了模型限制但白名单是空的
- **代码位置**：`middleware/distributor.go:68`
- **日志关键词**：`no access to any models`

### 8. 令牌分组无权访问

- **代码位置**：`middleware/auth.go:449`
- **日志关键词**：`Unauthorized to access group`

### 9. 分组已废弃

- **代码位置**：`middleware/auth.go:455`
- **日志关键词**：`has been deprecated`

### 10. 普通用户指定渠道

- **触发条件**：非管理员用户使用 `sk-xxx-channelId` 格式指定 channel
- **代码位置**：`middleware/auth.go:496`
- **日志关键词**：`specified channels are not supported`

## 四、日志检索命令

### 4.1 日志文件说明

- **文件命名格式**：`api-YYYYMMDDHHMMSS.log`（`logger/logger.go:55`）
- **归档格式**：`.gz` 压缩后放到 `./archive/` 目录
- **业务错误日志格式**：`[ERR] 2026/07/02 - 10:30:15 | <RequestId> | user <userId> | <message>`
- **Gin 访问日志格式**：`[GIN] 2026/07/02 - 10:30:15 | 403 |   1.234ms | 1.2.3.4 | POST "/v1/chat/completions"`

### 4.2 常用检索命令

#### ① 按用户 ID + 关键词组合搜索（最常用）

```bash
# 搜归档 gz 文件
find ./archive -name "*202607*.gz" -exec zgrep -a "\[ERR\]" {} + \
  | grep -a "user 2061455220286103554 |" \
  | grep -aE "no access to model|channel has been disabled|has been banned|not in the list of allowed IPs|Unauthorized to access group|has been deprecated|specified channels are not supported|No permission to access|no access to any models|insufficient_privilege|Unable to resolve the client's IP|asset group limit reached|request blocked|insufficient_user_quota|订阅额度不足|pre_consume_token_quota_failed"
```

#### ② 归档 + 当天实时日志一起搜

```bash
{ find ./archive -name "*202607*.gz" -exec zgrep -a "\[ERR\]" {} + ; \
  grep -a "\[ERR\]" api-202607*.log 2>/dev/null ; } \
  | grep -a "user 2061455220286103554 |" \
  | grep -aE "no access to model|has been banned|channel has been disabled|not in the list of allowed IPs|Unauthorized to access group|has been deprecated|specified channels are not supported|No permission to access|no access to any models"
```

#### ③ 按 RequestId 精准定位（终极大招）

```bash
# 拿到用户提供的 X-Oneapi-Request-Id 后
grep "202606172117153065520798268d9d6ttx4cwnO" api-*.log
zgrep "202606172117153065520798268d9d6ttx4cwnO" ./archive/*.gz
```

#### ④ 按具体场景单独搜

```bash
# 令牌无权访问 model（最常见）
grep -aE "\[ERR\].*no access to model" api-*.log | tail -50

# 用户被封禁
grep -aE "\[ERR\].*has been banned" api-*.log | tail -50

# IP 白名单
grep -aE "\[ERR\].*not in the list of allowed IPs" api-*.log | tail -50

# 渠道被禁用
grep -aE "\[ERR\].*channel has been disabled" api-*.log | tail -50
```

#### ⑤ 统计次数 / 首末时间

```bash
# 某用户的 403 出现次数
find ./archive -name "*202607*.gz" -exec zgrep -ac "user 2061455220286103554" {} + \
  | grep -v ":0$"

# 首次和末次出现时间
find ./archive -name "*202607*.gz" -exec zgrep -a "user 2061455220286103554 |" {} + \
  | grep -a "\[ERR\]" | head -1
find ./archive -name "*202607*.gz" -exec zgrep -a "user 2061455220286103554 |" {} + \
  | grep -a "\[ERR\]" | tail -1
```

### 4.3 数据库查询（额度类 403 必用）

额度类 403 **不写 SysLog**，必须查数据库 `logs` 表：

```sql
-- 查某用户最近的错误日志（type=5）
SELECT
  FROM_UNIXTIME(created_at) AS time,
  content,
  model_name,
  channel_id,
  token_name,
  request_id
FROM logs
WHERE user_id = 2061455220286103554
  AND type = 5
  AND created_at BETWEEN UNIX_TIMESTAMP('2026-07-01') AND UNIX_TIMESTAMP('2026-07-03')
ORDER BY created_at DESC
LIMIT 50;

-- 查某个 RequestId 的所有相关日志
SELECT * FROM logs WHERE request_id = '202606172117153065520798268d9d6ttx4cwnO';
```

## 五、日志类型分类速查表

| 场景类型 | 是否有 [ERR] 业务日志 | 是否写数据库 logs 表 | 定位方式 |
|---------|--------------------|-------------------|---------|
| 中间件层认证/授权 | ✅ 有 | ❌ 无 | grep SysLog |
| 中间件层分发 | ✅ 有 | ❌ 无 | grep SysLog |
| 额度/计费类 | ❌ **无** | ✅ 有（type=5）| 查数据库 |
| 控制器层业务 | ✅ 有 | 部分有 | grep SysLog |
| Webhook 类 | ❌ **无** | ❌ 无 | Gin access log |
| 上游返回类 | 部分有 | ✅ 有（type=5）| 查数据库 + 上游 provider 日志 |

## 六、Gin Access Log 兜底

如果上述方式都定位不到（Webhook 类等），必须去看 Gin 访问日志：

```bash
# 找出所有 403 请求
grep -aE "\[GIN\].*\| 403 \|" api-*.log | tail -50

# 找特定 IP 的 403
grep -aE "\[GIN\].*\| 403 \|" api-*.log | grep "1.2.3.4"

# 找特定路径的 403（比如 Stripe webhook）
grep -aE "\[GIN\].*\| 403 \|" api-*.log | grep "stripe/webhook"
```

## 七、附录：错误响应结构参考

### 中间件 + 大多数控制器返回

```json
{
  "error": {
    "message": "This token has no access to model gpt-4o (request id: xxx)",
    "type": "api_error",
    "code": ""
  }
}
```

### 部分控制器（`c.JSON` 直接返回）

```json
{
  "success": false,
  "message": "User has been banned"
}
```

### Webhook 类

- 只返回 HTTP 403 状态码，body 可能为空或纯文本
