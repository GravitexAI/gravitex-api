## 快速 FAQ

**Q: 同优先级的多个渠道，重试时会在它们之间多次尝试吗？**
A: 不会。同优先级只占 1 个梯度索引，retry=1 就降到下一个优先级了。详见 [02-重试机制与优先级梯度](./02-重试机制与优先级梯度.md)。

**Q: 多密钥渠道的第 11 个请求进来时，10 个密钥都"被占用"了怎么办？**
A: 密钥不存在"占用"。轮询索引只是一个指针，取完立刻释放，第 11 个请求正常拿到 key#0。详见 [03-并发场景与轮询索引](./03-并发场景与轮询索引.md)。

**Q: 想让某个高成本密钥只在其他密钥全失败时才使用？**
A: 必须把该密钥拆成独立渠道，设最低优先级。同一渠道内的密钥没有优先级区分。详见 [04-配置方案与最佳实践](./04-配置方案与最佳实践.md) 的"场景三：保底密钥"。

**Q: 优先级设成 999 和设成 1 有什么区别？**
A: 没有区别。系统只关心有几个**不同**的优先级值（梯度数），不关心具体数值大小。
