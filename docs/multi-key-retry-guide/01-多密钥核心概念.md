# 多密钥核心概念

## 什么是多密钥

一个渠道可以配置多个 API Key，以换行符 `\n` 分隔填入 Key 字段，并开启 `IsMultiKey`。系统会在每次请求时从中选取一个密钥使用。

## 三种密钥选择模式

### 1. 轮询模式（Polling）

```
key#0 → key#1 → key#2 → ... → key#9 → key#0 → key#1 → ...
```

- 严格按顺序依次使用，到末尾后从头循环
- 自动跳过被禁用的密钥
- 使用 per-channel 互斥锁保证并发安全
- 索引持久化：内存缓存模式下保留在内存，否则每次写入数据库

**适用场景**：密钥有 RPM/TPM 限额，需要严格均匀分散流量。

### 2. 随机模式（Random）

```
随机从启用的密钥中选一个
```

- 大样本下近似均匀
- 无状态，不需要持久化索引
- 并发安全（每次调用独立随机）

**适用场景**：密钥无差别，只需要负载均衡。

### 3. 默认模式（未设置）

```
始终使用第一个启用的密钥
```

- 如果第一个密钥被禁用，使用第二个，以此类推
- 类似主备关系

**适用场景**：有明确的主备密钥关系。

## 密钥选择模式对比

| 特性 | 轮询 | 随机 | 默认 |
|------|------|------|------|
| 均匀性 | 严格均匀 | 近似均匀 | 不均匀（集中在第一个） |
| 状态依赖 | 需要持久化索引 | 无状态 | 无状态 |
| 并发安全 | 互斥锁保护 | 天然安全 | 天然安全 |
| 跳过禁用密钥 | 支持 | 支持 | 支持 |
| 推荐缓存配置 | Redis + 内存缓存 | 无要求 | 无要求 |

## 轮询模式的缓存依赖

轮询模式的核心是一个全局共享的轮询索引 `MultiKeyPollingIndex`。这个索引需要在请求间持久化：

| 缓存模式 | 索引存储位置 | 每次选 key 的开销 | 多实例一致性 |
|---------|------------|-----------------|------------|
| 内存缓存开启 | 进程内存 | 纳秒级（只需内存锁） | 各实例独立轮询 |
| 内存缓存关闭 | 数据库 | 毫秒级（读DB + 写DB） | 通过 DB 同步 |
| Redis 开启 | Redis | 微秒级 | 全局一致 |

**建议**：轮询模式务必开启内存缓存，否则高并发下数据库成为瓶颈。

## 密钥状态管理

每个密钥有独立的状态，存储在渠道的 `ChannelInfo` 中：

```
MultiKeyStatusList:       map[密钥索引]状态      // 被禁用的密钥记录在此
MultiKeyDisabledReason:   map[密钥索引]禁用原因
MultiKeyDisabledTime:     map[密钥索引]禁用时间戳
```

- 未出现在 `MultiKeyStatusList` 中的密钥默认为启用状态
- 密钥被禁用后，轮询/随机模式会自动跳过它
- 管理员可以在渠道管理界面手动恢复

## 密钥自动禁用

当请求失败且满足以下条件时，系统会自动禁用**出错的那一个密钥**（不是整个渠道）：

| 触发条件 | 说明 |
|---------|------|
| `invalid_api_key` | API Key 无效 |
| `account_deactivated` | 账户被停用 |
| `billing_not_active` | 计费未激活 |
| `insufficient_quota` | 额度不足 |
| `authentication_error` | 认证错误（如 Claude） |
| `permission_error` / `forbidden` | 权限错误 |
| 配置的自动禁用状态码 | 如 HTTP 401 |
| 配置的自动禁用关键词 | 错误信息匹配 |

**前提**：渠道必须开启 `AutoBan`（自动禁用）功能。

### 整渠道禁用

当一个多密钥渠道的**所有密钥都被禁用**时，整个渠道自动标记为 `AutoDisabled`，不再参与渠道选择。

```
10 个密钥的渠道：
  key#3 报错 → 禁用 key#3，渠道正常
  key#7 报错 → 禁用 key#7，渠道正常
  ...
  所有 10 个都被禁用 → 整个渠道自动下线
```
