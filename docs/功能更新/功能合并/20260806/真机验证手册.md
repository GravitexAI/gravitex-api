# 真机验证手册（阶段1-4 合并后上线前必做）

> 为什么必须真机：离线差分已经证明**代码算钱的逻辑没变**（617 行输出逐字节一致）。
> 但差分测不到一件事——**上游真实返回的 JSON 字段名有没有对上**。
> 比如 Anthropic 把 `cache_creation` 改名了，我们解析不到就当 0 处理，静默少收钱。

**通用做法**：每项发一次请求 → 记下 `request_id` → 去数据库查这条日志 → 对照期望值。

```sql
-- 查最近一条日志的完整计费信息
SELECT id, model_name, prompt_tokens, completion_tokens, quota, other
FROM logs WHERE user_id = <你的用户ID> ORDER BY id DESC LIMIT 1;
```

`other` 字段是 JSON，计费明细都在里面。下面每项会说清楚该看哪个 key。

---

## 1. Claude prompt cache 计费

**为什么测**：本次官方修了一个**重复计费**的真 bug（缓存创建 token 以前是相加，现在取最大值）。

**怎么发**：对同一个 Claude 模型连发两次，第一次带 `cache_control` 写缓存，第二次命中缓存。

```bash
curl https://<你的域名>/v1/messages \
  -H "Authorization: Bearer sk-xxx" -H "Content-Type: application/json" \
  -d '{
    "model":"claude-sonnet-4",
    "max_tokens":100,
    "system":[{"type":"text","text":"<这里放一段 2000 字以上的长文本>","cache_control":{"type":"ephemeral"}}],
    "messages":[{"role":"user","content":"总结一下"}]
  }'
```

**看什么**：
- 第一次：`other` 里 `cache_creation_tokens` > 0，`cached_tokens` = 0
- 第二次：`cached_tokens` > 0（命中），`cache_creation_tokens` = 0
- **额度**：缓存读取的部分应该明显比普通输入便宜（默认 0.1 倍）

**❌ 判定失败**：两个字段同时有值且额度约等于两者相加 → 重复计费又回来了。

## 2. GPT-5.6 缓存写入（cache_write_tokens）

**为什么测**：这是官方新加的字段，我们和官方的取值方式不同过。

**怎么发**：用 gpt-5.6 系列模型发一个长 prompt，带 `prompt_cache_key`。

**看什么**：`other` 里 `cache_write_tokens` 有值时，
额度 = 缓存创建价 × cache_write_tokens + 普通价 × 剩余部分。

**❌ 判定失败**：`cached_creation_tokens` 和 `cache_write_tokens` 都有值，
且额度是两者**相加** → 重复计费。正确是取**最大值**。

## 3. Gemini 图文分离计费

**为什么测**：main-alpha 有个 `CHZ-PATCH(gemini-usage-fix)` 定制，
把 Gemini 输出的图片 token 和文本 token 分开按不同价格算。这是我们独有的，官方没有。

**怎么发**：用 `gemini-3-pro-image` 之类的模型让它生成一张图。

**看什么**：`other` 里应该同时有
`gemini_image_output_tokens` 和 `gemini_text_output_tokens`，
两者分别按 `output_image_price` 和普通补全倍率计价。

**❌ 判定失败**：只有一个总的 completion_tokens，图片按文本价算 → 定制丢了。

---

## 4. Gemini Omni 视频输入计费

**怎么发**：给 Gemini 传一个视频文件做理解。

**看什么**：`other` 里 `video_tokens` 有值，且按视频倍率单独计价。

---

## 5. 视频按秒计费

**怎么发**：提交一个 veo / 可灵 / 豆包的视频生成任务，等它完成。

**看什么**：
- 提交时先预扣一笔（按预估时长）
- 完成后按**实际时长**重算，多退少补
- `other` 里有 `official_video_price_per_second` 和实际秒数

**❌ 判定失败**：提交后额度没变化，或者完成后没有重算。

**注意**：这条要测两遍——一次让它**成功**，一次让它**失败**，
失败必须**全额退款**（本次官方修了 Suno 重复退款的 bug，顺手验一下不会退两次）。

## 6. 视频按量（token）计费

**怎么发**：提交一个按 token 计费的视频模型任务（如 ali wan 系列）。

**看什么**：`other` 里 `video_tokens` 按倍率计价，不是按秒。

## 7. ali wan 系列视频（13 个模型）

**为什么单独测**：main-alpha 给 ali 的 adaptor 写了一整套计费引擎（`BillingResolutionKeyFromParams`），
按分辨率+时长查价，官方没有。

**怎么发**：至少挑 2 个不同分辨率的 wan 模型各发一次。

**看什么**：不同分辨率的单价确实不同，且和后台配的价格表对得上。

---

## 8. gpt-image 按张计费

**为什么测**：main-alpha 独有的按张计费（官方是按 token）。

**怎么发**：两个接口都要测。

```bash
# 生成：一次出 3 张
curl https://<域名>/v1/images/generations -H "Authorization: Bearer sk-xxx" \
  -d '{"model":"gpt-image-1","prompt":"a cat","n":3,"size":"1024x1024"}'

# 编辑：带 2 张输入图
curl https://<域名>/v1/images/edits -H "Authorization: Bearer sk-xxx" \
  -F model=gpt-image-1 -F 'prompt=make it blue' -F image[]=@a.png -F image[]=@b.png
```

**看什么**：
- `other` 里有 `image_billing_usage`，含输入张数、输出张数、尺寸档位
- 额度 = 首张输入价 + (输入张数-1)×后续张价 + 输出张数×对应尺寸档价
- 换个尺寸（`1024x1536`）再发一次，单价应该跟着变

**❌ 判定失败**：额度和张数无关，只和 token 数有关 → 按张计费丢了。

## 9. 阶梯计费表达式

**怎么发**：在后台给某个模型配一个带条件的表达式，比如：

```
len<=200000 ? P*0.000003+C*0.000015 : P*0.000006+C*0.00003
```

然后发两个请求：一个短 prompt（走第一档），一个超长 prompt（走第二档）。

**看什么**：两次的单价确实不同，且 `other` 里能看到命中的档位。

**顺带验重试换组**（本次官方修的）：把第一个分组的渠道全禁用，
让请求重试到第二个分组，确认**最终按第二个分组的倍率结算**，不是第一个。

## 10. RuoYi JWT 单点登录

**为什么测**：官方本次把这段整个删了，我们拒绝了这个改动。要确认还活着。

**怎么测**：从 Java 管理后台点跳转到 Go 网关的页面，**不应该要求重新登录**。

**❌ 判定失败**：跳过去要求登录 → RuoYi 鉴权链路断了。

**快速自查**（不用真机）：
```bash
grep -c tryRuoYiJWTAuth middleware/auth.go   # 应该是 2
```

## 11. 双前端切换

**为什么测**：官方本次删了 `web/classic`，我们拒绝了。

**怎么测**：
1. `cd web/default && bun install && bun run build`
2. `cd web/classic && bun install && bun run build`
3. 编译后端并启动
4. 后台切换主题为 `classic` → 页面应该变成旧版界面
5. 切回 `default` → 变回新版

**❌ 判定失败**：切换后 404 或者一直是同一套界面。

## 12. OperLog 操作日志

**怎么测**：进 `/console/setting?tab=ratio`，改任意一个倍率并保存。

**看什么**：
- 弹出"确认改动并填写操作日志"对话框
- 保存后 `oper_log` 表有新记录，改动前后的值都记上了
- 渠道管理页的"日志"按钮能看到记录
