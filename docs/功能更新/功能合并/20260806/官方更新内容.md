## 一、三次伤筋动骨的重构（本次的主线）

官方这段时间做了三件"动骨头"的事，我们全部跟进了。

### 1. 计费流程改成"计费会话"

**以前**：预扣费、退款、结算三件事散在各处，每个调用方自己拼。
**现在**：抽象成一个 `BillingSession` 对象——开一次会话，预扣、追加预留、结算、退款都走它。

好处是不容易漏退款、不容易重复扣。比如"重试时换了个分组"这种场景，
以前要各处自己判断，现在会话统一处理。

**对我们的影响**：main-alpha 的欠费放行（`AllowNegativeBalance`）原本有 6 个检查点，
其中 2 个所在的文件被官方这次重构整个删掉了，职责由计费会话接管——
新代码里那 2 个检查**依然在**，只是搬了家。功能没丢。

### 2. 登录改成"无状态 token"

**以前**：管理后台登录靠服务端 session（服务端记着谁登录了）。
**现在**：改成无状态 token + 独立的会话管理表（能看到自己在哪些设备登录、能踢掉某个设备）。

**⚠️ 这次官方顺手把 RuoYi JWT 鉴权整段删掉了**——那是我们 Java 端和 Go 端单点登录的关键链路。

**我们的处理**：**拒绝**这次 auth 改写，保住 RuoYi SSO。
官方的会话管理功能（多设备管理）作为独立待办，将来单独做，做的时候必须连带保住 RuoYi。

> ✅ **2026-08-07 已补做（A2 完整版）**：官方新前端 `web/default` 期望的是"token bundle + 无状态 access_token + 持久化登录会话"这套鉴权，而 fork 原来的扁平 cookie 登录喂不出这个响应，导致 default 前端登录后无限刷新。已按 A2 完整版补齐：新增 `login_session` 表（多设备管理 + 远程下线）、`service/auth_token.go`（access_token / 2FA flow_token 两种 JWT，用 `SessionSecret` 签名）、`setupLogin` 同时吐"扁平字段(classic)+ token bundle(default)"、`controller/auth_session.go` 的 refresh/logout/sessions 接口、2FA 走 flow_token。**RuoYi SSO 完整保留**，且 access_token JWT 鉴权层被放在 RuoYi 层**之前**（详见[防丢清单 5.3 / 5.7](../main-alpha_独有功能清单.md)）。已真机验证：default 前端登录不再无限刷新、classic cookie 登录与 RuoYi 跳转均正常。

### 3. 协议转换抽成独立模块 relaykit

这是最大的一次（368 个文件）。

**以前**：OpenAI ↔ Claude ↔ Gemini 三种协议互转的代码，和网关的业务代码（数据库、
计费、gin 框架）混在一起。
**现在**：抽成一个独立的 Go 子模块 `relaykit/`，只依赖 5 个第三方包，
不碰数据库、不碰 gin。等于把"翻译器"从"网关"里剥出来了。

好处是转换逻辑能单独测试、单独复用，官方还给它配了一套"金标准快照测试"
（固定输入 → 固定输出，改坏了立刻发现）。

**对我们的影响**：`dto/` 目录整体搬到了 `relaykit/dto/`。
这是本次合并工作量最大的部分，但 git 自动识别了文件重命名，
main-alpha 加的字段（豆包 AK/SK、Qwen 扩展参数等）全部跟着搬过去了，一个没丢。

## 二、计费相关的修复（最该关注的部分）

### 2.1 OpenAI 缓存写入按"缓存创建价"计费

GPT-5.6 开始，OpenAI 会单独上报一个 `cache_write_tokens`（缓存写入）。
官方现在按缓存创建价计费，并且做了**零值钳制**——不会算出负数。

⚠️ **这条我们特别关注过**：main-alpha 之前是把
`cached_creation_tokens + cache_write_tokens` **相加**，
但上游有时两个字段都会上报，相加就是**重复计费**。
官方改成取两者的**最大值**，我们已吸收（`CacheCreationTokensTotal()`）。
**这是一个真实的多收钱 bug，已修复。**

### 2.2 未缓存部分的 token 数收敛

计算"没走缓存的那部分 prompt"时，以前可能算出比整个 prompt 还大的数。
现在用 `prompt - max(缓存读, 缓存写)` 兜底，不会超。

### 2.3 阶梯计费在"重试换组"时的正确性

一个请求失败重试、并且换到了另一个分组时：
- 预留额度会按新分组重新计算（额度不够会提前拦住）
- 最终结算按**实际用的那个分组**算，不是按最初的分组

以前这里可能按错误的分组倍率结算。

### 2.4 预扣费额度溢出直接拒绝

预扣费算出来的额度如果大到溢出（int32 上限），以前会回绕成负数变成"送钱"，
现在直接拒绝这个请求并报错。

### 2.5 Suno 任务重复退款

Suno 任务失败退款时，如果并发触发了两次，会退两次钱。
现在用数据库的 CAS（比较并交换）保证只退一次。

### 2.6 订阅重置的行锁

订阅额度重置改用 GORM v2 的行锁，避免并发重置导致额度算错。

### 2.7 用户额度大数溢出

管理端给用户设置超大额度时前端会溢出显示错误，已修。

## 四、其他新功能

### 4.1 工具调用价格可配置
搜索、代码解释器这类"内置工具"的调用费用，现在可以在后台单独配价，
不用再写死在代码里。同时新增了 alpha 搜索的计费。

### 4.1b 阶梯计费新增「请求规则计费（条件倍率）」（#6561，本文档当时漏记，2026-08-25 补）
> 官方 `feat(billing): highlight matched conditional multipliers in logs (#6561)`。

在「阶梯计费」之上加了一层**条件倍率**：给模型定价追加若干规则，**请求满足条件时把最终价格乘以一个倍率**（`>1` 加价、`<1` 折扣、多条命中连乘）。条件可读**时段**（`hour/minute/weekday/month/day` + 时区）、**请求参数**（`param`）、**请求头**（`header`）。典型用途是**波峰波谷 / 分时计费**（如 DeepSeek 错峰折扣、工作日高峰全价其余半价）。命中的规则会写进消费日志 `other.request_rules` 并在用量日志里高亮。
> 详细配置见 **[请求规则计费（条件倍率）使用指南](../../请求规则计费(条件倍率)使用指南.md)**。

### 4.2 定价页新增"未设价模型"标签页
一眼看出哪些模型还没配倍率——以前只能一个个翻。
配套修了几个问题：只列该渠道实际有的模型、批量复制、备注对比。

### 4.3 日志新增"流式状态"和"耗时指标"
- 流式请求的完成状态（正常结束 / 客户端断开 / 上游中断）现在对日志所有者可见
- 流式日志能看到首字延迟、总耗时这类指标

> ⚠️ 我们的调整：这些字段**只给管理员看，对普通用户隐藏**
> （`reject_reason` / `stream_status` / `official_quota` 等）。

### 4.4 Playground 新增参数面板
可以直接在体验页调温度、top_p 这些参数，不用改代码。

### 4.5 渠道级 HTTP 传输控制
每个渠道可以单独配连接超时、连接池这类底层参数。
以前是全局一套配置，一个慢上游会拖累所有渠道。

### 4.6 支持 zstd 压缩请求
客户端可以用 zstd 压缩请求体，省带宽。

### 4.7 OIDC 登录名称可自定义
登录页上 OIDC 按钮的文字可以改了（比如改成"用公司账号登录"）。

### 4.8 模型搜索加过滤条件
按"状态"和"是否已同步"过滤模型。
