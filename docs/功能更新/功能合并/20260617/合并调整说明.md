# 合并过程中 Alpha 的调整说明

本文档说明在将官方更新合入 alpha 分支时，哪些地方以 **alpha 为主**、哪些地方**接受了官方的改动**，以及对现有功能的潜在影响。

---

## 一、完全接受官方改动（alpha 功能不受影响）

| 官方改动 | 处理结果 | 说明 |
|---------|---------|------|
| Codex OAuth 授权流程下线 | ✅ 接受删除 | 已确认 alpha 未使用此功能，官方删除了这套 OAuth 流程，合并时同步删除 |
| 官方新增的前端（default 新 UI） | ✅ 接受引入 | 新 UI 框架文件完整引入，不影响现有 classic 前端的任何功能 |
| 日志新增审计记录字段 | ✅ 接受引入 | 额外记录一些审计信息，不影响现有日志查看 |
| 渠道测试对话框交互修复 | ✅ 接受 | 纯体验改进，无功能影响 |
| 安全审计日志 | ✅ 接受引入 | 新增功能，不影响现有逻辑 |
| Waffo Pancake 支付 | ✅ 接受引入 | 新增支付渠道，不影响现有支付方式 |
| 上游请求 ID 追踪 | ✅ 接受引入 | 新增字段，日志页面会多一列上游请求 ID |
| 模型性能指标采集 | ✅ 接受引入 | 后台新增性能看板，不影响业务流程 |

---

## 二、Alpha 覆盖官方（以 alpha 逻辑为主）

### 2.1 视频任务处理（影响较大）

**处理方式：** 保留 alpha 的完整视频任务逻辑，官方的版本被丢弃。

**原因：** 官方只有一个非常基础的视频任务框架（约 300 行），而 alpha 有完整实现（约 2100 行），覆盖了以下所有视频相关功能：

- Seedance 视频生成（含素材库、虚拟人像）
- AzureVideo（Azure 视频任务）
- Uptoken 上传 Token 服务
- 可灵（Kling）v3 系列视频
- 即梦（Jimeng）视频
- 豆包（Doubao）视频
- Vidu 视频
- Hailuo 视频

**影响：** 上述所有视频任务功能**正常保留**，官方的简化版不适用于 alpha 的使用场景。

---

### 2.2 Gemini 图片响应格式（影响 Gemini 图片生成结果展示）

**处理方式：** 保留 alpha 的实现。

**官方做法：** 把 Gemini 返回的图片转成 Markdown 格式（`![image](...)`）嵌在文字里。

**Alpha 做法：** 把 Gemini 返回的图片转成 OpenAI 标准的图片格式，作为独立的图片内容块返回。

**影响：** 通过 API 调用 Gemini 图片生成时，客户端收到的是 OpenAI 标准格式的图片内容（base64），而不是 Markdown 文字。对接了 API 的业务（如前端 CLI 工具）能正常显示图片，Markdown 格式在这里反而不合适。

---

### 2.3 Claude 版本判断逻辑（影响 Claude 新模型支持）

**处理方式：** 保留 alpha 的实现。

**官方做法：** 用写死的模型名前缀判断是否是 Claude Opus 4.7+ 版本（只认识 4.7、4.8）。

**Alpha 做法：** 用一个版本比较函数判断（只要版本号 ≥ 4.7 都支持）。

**影响：** alpha 的方式更灵活，未来官方出 claude-opus-4.9、4.10 时无需改代码自动支持；官方写死的方式每次新模型出来都要手动更新。**功能上对现有模型无影响。**

---

### 2.4 图片生成保真度（InputFidelity）参数处理

**处理方式：** 类型调整为指针字符串，逻辑保持官方的验证逻辑。

**影响：** gpt-image 系列模型的 `input_fidelity` 参数（`low`/`medium`/`high`）现在可以正确传递给上游，之前 alpha 里这个字段是通用格式，官方新增了明确的枚举验证。**功能正常，无负面影响。**

---

### 2.5 图片生成质量计费逻辑

**处理方式：** 保留 alpha 的详细计费逻辑。

**官方做法：** 简化了图片质量参数的处理。

**Alpha 做法：** 保留了详细的 quality 参数映射和按质量分级计费的逻辑。

**影响：** 图片生成计费按 alpha 的规则执行，质量参数（standard/hd）对应的费率计算不变。

---

## 三、两边合并（功能叠加，互不影响）

| 功能点 | Alpha 保留 | 官方新增 | 叠加效果 |
|-------|-----------|---------|---------|
| 渠道列表查询 | 按 Region（区域表）路由 | 按 Group 分组过滤 + 多字段排序 | 两者并存，渠道列表同时支持 Region 路由和分组过滤 |
| 渠道粘性处理 | 自定义亲和度逻辑 | 禁用渠道时可配置是否清空粘性 | 都保留，配置项正常工作 |
| Claude 中继处理 | Mythos 系列采样策略覆盖、tool_choice 覆盖 | 小幅 bug 修复 | Alpha 策略保留，官方修复也引入 |
| 渠道标签管理 | 支持 Region 参数 | 新增 Group 基础的分页查询辅助函数 | 都保留，标签查询功能增强 |
| 错误重试日志 | 重试链路记录（retry_count、retry_chain） | 性能指标采集（relay 失败时上报） | 两者都执行，重试日志和性能指标都会记录 |
| 日志字段 | RetryFail 类型日志、价格链路、vendor_id | 审计信息、上游 Request ID | 字段叠加，日志更丰富 |
| Vertex AI 任务 | AzureVideo 和 Uptoken 双模式（API Key + Service Account） | 小幅修复 | Alpha 的双认证模式完整保留 |
| 模型价格表 | Mythos 系列、claude-opus-4-9/4-10 等自定义模型价格 | claude-opus-4-8 等官方新模型价格 | 都加入价格表，各自模型正常计费 |
| 缓存比例配置 | Mythos 系列模型缓存比例 | 部分官方新模型缓存比例 | 合并后两边的配置都生效 |

## 四、前端相关

### 4.1 经典前端（用户实际使用的那个）

**影响：无功能变化。** Alpha 的经典前端逻辑全部保留，包括：
- 自定义的 Footer 组件（保留 alpha 版本，官方有不同设计）
- 渠道日志弹窗（alpha 新增的功能，完整保留）
- 用量日志的 Gemini 输出分项计费展示（alpha 特有，保留）
- vite 构建配置（alpha 还在用 vite，保留；官方迁移到 rsbuild）

### 4.2 新增的官方默认前端

官方新 UI 的所有文件引入了进来，但**目前不会自动启用**（因为没有预构建产物）。如需启用新前端，需要在 `web/` 目录下单独执行前端构建。

---

## 五、需要注意的地方

1. **视频任务功能完全依赖 alpha 的实现**，如果后续官方对视频任务做了重大更新，合并时需要特别留意 `controller/task_video.go` 文件的冲突处理，以 alpha 为基础逐项评估。

2. **新前端（default）目前未构建**，如果希望提供给用户体验新 UI，需要单独执行 `cd web && bun install && bun run build` 进行构建，并在配置中开启。

3. **Codex OAuth 已永久删除**，如果未来发现有用户曾使用过 Codex OAuth 功能，相关功能已不可用，需重新实现或告知用户改用其他方式。
