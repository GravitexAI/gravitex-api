# 插件接管生图（OpenAI Images 协议）：本次未启用的原因与后续方案

> 状态：**待做（用户 2026-11-11 确认先记录）**。对应官方 #141 `03563a4a7`（feat(plugins): serve OpenAI Images API through task plugins）、#172 `87bb71e7f`（豆包插件 Seedream 图片）。
> 关联：[合并调整说明.md](合并调整说明.md) 第 6 批。

## 一、官方做了什么

1. 新增宿主协议 `openai_image`：任务插件可以认领模型，处理 `/v1/images/generations`、`/v1/images/edits`。宿主在请求内轮询插件任务，等结果出来后按 OpenAI Images 格式返回。
2. `/v1/images/*` 改由插件协议路由注册（`router/task-plugin-protocol-router.go`）：模型被插件认领就走插件，没被认领才回落到普通中转（`controller.Relay`）。
3. **阿里百炼图片模型整体迁到 alibaba 插件**：删除 ali 渠道原生图片适配器（`relay/channel/ali/image.go`、`image_wan.go`）、qwen 模型配置（`setting/model_setting/qwen.go`），以及 z-image 提示词扩写加价、`parameters.n` 下发等阿里专用逻辑。
4. 豆包插件新增 Seedream 生图，按插件 `usageSchema` 和表达式计费。
5. 任务消费日志新增 `task_sync`（请求内同步交付）、`image_count`、`result_discarded` 等字段。

## 二、本次为什么没启用

照官方启用后，被插件认领的生图请求会**绕过 alpha 的 `relay/image_handler.go`（ImageHelper）**，下面这些 alpha 能力会失效：

| alpha 能力 | 位置 | 影响 |
|---|---|---|
| Seedream 逐张尺寸分档、拆图输出折扣 | `helper.SettleImagePerImageUsage`、`ImagePerImagePricing`（清单 3.7） | 计费口径变化 |
| 按上游实际生成张数结算（请求 n=4 实际 1 张按 1 张收） | ImageHelper `UpdateImageCount(GeneratedImages)` | 可能多收 |
| 阿里原生生图（含供应商拨号防护、z-image 加价、显式 `parameters.n`） | `relay/channel/ali/*` | 官方删除后阿里渠道生图不可用 |
| gpt-image 自动升级 edits、请求/上游 body 调试日志 | ImageHelper | 行为与排障能力丢失 |
| alpha 任务日志格式（map，Java 渲染依赖） | `service/task_billing.go` | 字段差异 |

## 三、本次的处理（当前状态）

- `router/task-plugin-protocol-router.go` 跳过 `openai_image` 协议注册；`router/relay-router.go` 保留 `/v1/images/generations`、`/v1/images/edits` → `controller.Relay`
- 恢复 `relay/channel/ali/*`、`setting/model_setting/qwen.go`、`common/model.go`（`ZImagePromptExtendMultiplier`）、`relay/image_handler.go`、`service/image_billing.go`（promptExtend 参数）、`relay/helper/price.go` 中阿里图片计费
- 删除 `controller/plugin_protocol_image.go`；`controller/plugin_protocol.go` 保持 alpha
- 插件 JS 中的图片规格（alibaba 的 wan/qwen/z-image、doubao 的 Seedream）保留，不注册路由即不生效

## 四、后续启用方案

1. **把 alpha 图片计费规则移植进插件**
   - doubao 插件：Seedream 逐张尺寸分档、拆图折扣、按实际返回张数结算（`extractUsageOnComplete` 读取实际张数）
   - alibaba 插件：z-image `prompt_extend` 加价、`parameters.n` 显式下发
   - 用 alpha 现有计费测试（`relay/helper` Seedream 分档、image_handler 张数结算）做对拍，同一输入两条路径计费结果一致
2. **按模型灰度**：给 `openai_image` 认领加白名单配置（例如 `task_plugin_image_models`），只有白名单内的模型走插件，其余继续走 ImageHelper；先放量新模型，再迁存量
3. **路由恢复官方写法**：去掉 protocol router 的 `openai_image` 跳过逻辑，`/v1/images/*` 交给协议路由，未认领模型自动回落 Relay
4. **阿里渠道**：迁移完成、对拍通过后再删除 `relay/channel/ali/image*.go`；迁移期间两条路径并存
5. **日志**：任务日志补 `task_sync`、`image_count`，保持 Java 渲染需要的 map 字段不变
6. **验收**
   - [ ] Seedream 各尺寸档位、n>1 实际少出图的计费与 ImageHelper 一致
   - [ ] 阿里 wan/qwen/z-image 生图在插件路径下可用且计费一致
   - [ ] 未认领模型（gpt-image 等）继续走 ImageHelper，行为不变
   - [ ] 消费日志字段与 Java 侧渲染兼容
