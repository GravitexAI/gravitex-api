# 官方 main 分支更新内容（2026-06-22 至 2026-07-02）

本次同步了官方 48 个提交。以下按功能模块整理。

---

## 一、后台权限系统升级：细粒度授权（authz）

**这是本次最大的架构变化。** 官方引入了一套基于 Casbin 的细粒度权限系统，管理员可以按资源（渠道/日志/用户等）+ 动作（读/写/敏感写/操作）分别授权。

- 新增数据库表 `casbin_rule` 和 `authz_role`，用于存储角色和策略
- 后台设置页面新增「权限管理」，可以给管理员账号配置精确到 API 端点的权限
- 老的 `RoleCommonUser/RoleAdminUser/RoleRootUser` 三级角色继续可用，作为默认权限模板
- 后端新增 `middleware.RequirePermission(perm)` 中间件，替代原来的 `middleware.AdminAuth()`
- 集群部署下，权限策略会通过 `authz.StartPolicySync` 周期性同步

**对运维的影响**：首次启动会自动建表并初始化默认策略，无需手动操作。

---

## 二、系统任务运行器（SystemTaskRunner）

**替代了原来散装的 goroutine 启动方式。** 官方把周期性任务统一到一个调度器：

- 新增数据库表 `system_tasks`（任务实例）和 `system_task_locks`（跨实例锁）
- 4 个内置任务：
  - `channel_test`（周期性渠道测试）
  - `model_update`（上游模型清单检测）
  - `midjourney_poll`（MJ 任务轮询）
  - `async_task_poll`（Suno/视频任务轮询）
- 后台新增「系统信息」页面，可以看到所有节点、所有任务的运行状态和历史
- 支持"手动触发一次"、"任务日志清理"等操作

**对运维的影响**：
- 集群部署下，多个 master 节点会自动通过 DB lease 抢锁，只有一个节点执行任务，无需手动配置主从
- 老的 `ENABLE_TASK_POLLING` 环境变量已废弃，改用 `UPDATE_TASK` + 每个 handler 的 `Enabled()` 检查
- 我们 main-alpha 原来的 `UpdateMidjourneyTaskBulk` / `UpdateTaskBulk` / `StartChannelUpstreamModelUpdateTask` 都已被此系统接管，不再单独启动

---

## 三、OpenAI Responses ↔ Chat 双向转换重构（relayconvert）

- 新增 `service/relayconvert/` 包，把 OpenAI Responses API 和 Chat Completions API 的相互转换独立成模块
- 支持 Responses → Chat 的完整转换（原来只支持 Chat → Responses）
- Playground（在线试用界面）迁移到新转换器，聊天体验和 Markdown 渲染改善
- 修复了流式响应下 tool_call 参数增量、reasoning_summary 分隔等边界问题

**面向使用者**：Playground 里试用模型时更流畅，Markdown 代码块、Reasoning 折叠展示更清爽。

---

## 四、被动渠道监控模式（Passive Monitor）

- 新增被动监控开关：只在渠道出现真实错误时才禁用，不做主动的健康探测
- 后台「渠道监控」设置新增模式选项：`disabled`（关闭）、`active`（主动测试）、`passive_recovery`（被动+自动恢复）、`scheduled_all`（全量周期测试）
- 减少了大规模渠道下的主动探测开销

---

## 五、ClickHouse 日志数据库正式支持

**注意**：官方支持的是标准 ClickHouse，我们 main-alpha 用的是 ByteHouse（CnchMergeTree 引擎，官方 MergeTree 无法建表），所以我们 `migrateLOGDB` 里对 ClickHouse 分支 skip AutoMigrate，继续用手动建表（见 `docs/bytehouse_logs.sql`）。

官方新增内容（仅供参考，我们不启用）：
- `LOG_SQL_CLICKHOUSE_TTL_DAYS` 环境变量控制日志 TTL 自动清理
- 自动建表脚本 `migrateClickHouseLogDB`（用 `ENGINE = MergeTree()`）
- ClickHouse 专用的 LIKE 模式转义（我们 ByteHouse 已经用了同样逻辑）

---

## 六、SMTP 邮件增强

- 支持 SMTP STARTTLS 模式（老版本只支持 SSL/TLS 或明文）
- 支持 NTLM 认证（企业内部 Exchange 场景）
- 新增环境变量：`SMTP_STARTTLS_ENABLE`、`SMTP_INSECURE_SKIP_VERIFY`

---

## 七、渠道管理界面改进

- 渠道卡片选择状态同步修复（多选后再点单个不会错乱）
- 渠道列表 UI 微调：section 标题、字段布局、行操作按钮体验优化
- 新增「异步轮询延迟」渠道级开关（`disable_task_polling_sleep`）：跳过异步任务轮询间隔，加快视频/Suno 任务反馈
- 新增自定义路由高级编辑器（advanced custom route editor）优化

---

## 八、User Token 限额

- 后台新增「系统设置 → 请求限制」章节，可以配置**每用户 token 数量上限**（防止个别用户创建过多 token）
- 用户端 token 管理页面在超限时会给出提示

---

## 九、系统实例信息面板（System Info）

- 后台新增「系统信息」页面，展示当前集群中所有存活的实例
- 每个实例上报自己的节点名（`NODE_NAME` 环境变量或 hostname）、启动时间、版本
- 用于多节点部署时快速排查哪台机器在跑
- 关联的新数据库表：`system_instances`

---

## 十、其他修复与改进

### 前端
- 修复默认前端主题切换后路由 404（切换后重置到首页）
- 富文本内容渲染安全加固（防 XSS）
- Markdown 渲染器统一，支持更多语法

- 模型定价页面切换模型时刷新阶梯计费编辑器
- 官方 Waffo 商品配置更新，Webhook SDK 升级

### 后端

- 主流 Go 依赖升级：`golang.org/x/crypto v0.48.0`、`net v0.50.0`、`sys v0.41.0`、`clickhouse-go v2.32.0`
