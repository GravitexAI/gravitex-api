## 二、Alpha 覆盖官方（以 alpha 逻辑为主）

### 2.1 model/log.go — Log 序列化 + LogType 常量

**处理**：保留 alpha 的 `MarshalJSON`（把 `Id` 和 `UserId` 都字符串化）+ alpha 的 `CreateLog`（大写，包含 LogBuffer + `ensureQuotaStreamEventIDOnLog`），只吸收官方新增的 `ensureLogRequestId`、`clickHouseLogOrder`、`assignDisplayLogIds` 辅助函数。

**关键差异**：
- 官方引入了小写 `createLog(log *Log) error`（简单包装），alpha 有大写 `CreateLog` 且被多个 controller 调用。合并时把官方 `createLog(log)` 的调用全部改回 `CreateLog(log)`，避免破坏 alpha 的调用方（`controller/asset.go`、`controller/relay.go`、`controller/task_video.go`）。
- LogType 常量：alpha 有 `LogTypeRetryFail=7`、`LogTypeTest=8`，官方 `LogTypeLogin=7`。合并后 alpha 的编号：`RetryFail=7 / Test=8 / Login=9`。

### 2.2 model/user.go — User struct

**处理**：接受官方新增的 `AdminPermissions` 字段和 `Group varchar(64)`（原 alpha 256，按主人指示改 64），保留 alpha 的 `MarshalJSON` 把 `Id` 字符串化。

### 2.3 controller/channel.go — UpdateChannel

**处理**：完全采用官方的 `PatchChannel + common.Unmarshal` 直接反序列化设计，删除 alpha 的 local `updateChannelRequest` struct + Int64Flexible 转换（Channel.Id 是普通自增主键，不会精度丢失，不需要 Int64Flexible）。

**保留**：alpha 的"GORM Updates() 跳过 nil 指针字段"cost_discount 显式置 NULL 逻辑（把 `req.CostDiscount` 改成 `channel.CostDiscount`）。

### 2.4 controller/channel_authz.go — 字段分类

**处理**：官方 `channelNonSensitiveFields` map 添加了 `"cost_discount"`，否则 `TestChannelFieldsAreClassified` 会失败。

### 2.5 controller/channel-test.go — 循环体

**处理**：官方已重构了 disable/enable/UpdateResponseTime/sleep 逻辑到循环体前部，alpha 冲突块里是**冗余重复代码**，直接删除。

保留：`processChannelError(...)` 4 参数签名（alpha 的 `willRetry bool` 参数用于区分"重试"和"错误"日志类型，不能删）。

### 2.6 controller/user.go — UpdateUser

**处理**：保留 alpha 的额外角色权限检查（`canManageTargetRole(myRole, updatedUser.Role)`）和自定义 quota 增减逻辑（`calculateUpdatedQuota` + `SetUserQuota` + `recordUserAmountChangeLog`），同时吸收官方新增的 `authzTouched` + `authz.ReloadPolicy()` + `model.InvalidateUserCache` 逻辑。

### 2.7 dto/channel_settings.go — ChannelOtherSettings

**处理**：**字段并集**——保留 alpha 独有字段（`AzureModelApiVersions`、`ByteplusAssetAK/SK/Region/ProjectName`、`EnableModerationQuery`）+ 吸收官方新增字段（`DisableTaskPollingSleep`）。

### 2.8 main.go — 启动流程

**处理**：
- 保留 alpha 的 `service.StartTaskClearTask()`
- 保留 alpha 的 `relay.CompleteVideoTaskOnUpstreamSuccessFn` / `MergeVideoTaskDataWithUpstreamResponseFn` 钩子注入
- 吸收官方 `service.StartSystemInstanceReporter()` + `controller.RegisterScheduledSystemTasks()` + `service.StartSystemTaskRunner()`
- **删除** alpha 的手动 goroutine 启动（`UpdateMidjourneyTaskBulk` / `UpdateTaskBulk` / `StartChannelUpstreamModelUpdateTask`）——已被 SystemTaskRunner 取代
- 废弃 `ENABLE_TASK_POLLING` 环境变量（改用 `UPDATE_TASK`）

### 2.9 router/api-router.go — 路由结构

**处理**：官方把 channel 路由抽成 `registerChannelRoutes(apiRouter)` + `registerAuthzRoutes(apiRouter)`。**alpha 独有的 `assetAdminRoute`（BytePlus 素材库管理）单独保留**，紧跟这两行之后。

### 2.10 common/database.go — DatabaseType API 迁移

**处理**：完全采用官方新的 typed `DatabaseType` API（`SetMainDatabaseType`/`UsingMainDatabase(...)`），删除 alpha 原来的全局 bool（`UsingSQLite`/`UsingMySQL`/`UsingPostgreSQL`/`UsingClickHouse`）。

**扫尾**：alpha 只有 `model/log.go` 和 `model/main.go` 用了旧 API，全部改成新 API：
- `common.UsingClickHouse` → `common.UsingLogDatabase(common.DatabaseTypeClickHouse)`
- `common.UsingSQLite` → `common.UsingMainDatabase(common.DatabaseTypeSQLite)`（migrateTaskIDColumnLength）
- `common.UsingSQLite` → `common.UsingLogDatabase(common.DatabaseTypeSQLite)`（migrateLogRequestIdColumnLength，日志库场景）

### 2.11 common/init.go — 环境变量初始化

**处理**：保留 alpha 的 `RuoYiAuthEnabled` / `RuoYiJWTSecret` 读取，吸收官方的 `initNodeNameIdentity()`（把 `NodeName = os.Getenv("NODE_NAME")` 替换成官方更智能的版本，支持 fallback 到 hostname）。

### 2.12 common/utils.go — GetTimeString

**处理**：保留 alpha 的 UTC+8 时区（`time.Now().In(time.FixedZone("UTC+8", 8*60*60))`），吸收官方的 9 位纳秒精度（`%09d`）和新增的 `requestIdPrefix` + `NewRequestId()` 函数。

### 2.13 model/main.go — chooseDB

**处理**：完整采用官方新版本（isClickHouseDSN 支持 tcp://http://https:// 前缀，normalizeClickHouseDSN 自动加 `secure=true`），**唯一例外**：MySQL 分支保留 `common.GetEnvOrDefaultBool("MYSQL_PREPARE_STMT", false)`（默认 false，防高并发下 prepared statement 爆炸）。

`migrateLOGDB` 对 ClickHouse 分支保留 alpha 的 skip 行为（生产用 ByteHouse CnchMergeTree，不能用官方的 MergeTree 建表），但 main 引入的 `migrateClickHouseLogDB` + TTL 辅助函数**都保留作为 dead code**，未来切换原生 ClickHouse 可直接启用。

`DeleteOldLog` 保留 alpha 的 ClickHouse 拒绝逻辑（"ByteHouse 不支持删除日志操作"），叠加官方新加的 `if limit <= 0 { limit = 100 }` 默认值。

### 2.14 model/task.go — 新函数并存

**处理**：alpha 的 `repairTaskPrivateData`（修 GORM v2 batch Find 对 MySQL JSON 列的 Scanner 调用 bug）和官方新增的 `HasUnfinishedSyncTasks`（asyncTaskPollHandler.Enabled() 检查用）**两者并存**——无冲突，都保留。

### 2.15 service/task_polling.go — DispatchPlatformUpdate

**处理**：删除 alpha 的 `UpdateVideoTasksFn` 钩子，采用官方直接调用 `UpdateVideoTasks(ctx, ...)`。因为 main 上已经把 `service/task_polling.go` 完整重构，`UpdateSunoTasks` / `UpdateVideoTasks` 都是直接定义，不需要 controller -> service 的钩子注入。

### 2.16 relay/channel/claude/relay_claude_test.go — FormatClaudeResponseInfo 调用

**5 处冲突处理**：alpha 传 `&relaycommon.RelayInfo{}`（不会 panic），main-alpha 分支的 bingyu commit 传 `nil`（会在 `info.SetUpstreamResponsesField` 时 runtime panic）。**取 alpha 版本（`&RelayInfo{}`）**，bingyu 应该只是修 build error 没跑 runtime。

### 2.17 relay/channel/openai/chat_via_responses.go — 整个文件

**处理**：**完全取官方版本**（`relayconvert.ResponsesStreamEventToChatChunks`），alpha 内联的 190+ 行 switch case 被官方统一转换函数取代。功能等价（response.reasoning_summary_text.delta/done、response.output_item.added、response.function_call_arguments 等 event 全覆盖）。

### 2.18 go.mod / go.sum / web/bun.lock — 依赖锁文件

**处理**：先临时用 `git checkout --theirs` 占位，代码冲突全部解决后跑 `go mod tidy` 重新生成。`bun.lock` 采用官方版本，前端后续跑 `bun install` 会自动同步。
