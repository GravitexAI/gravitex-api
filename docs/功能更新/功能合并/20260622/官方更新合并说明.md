## 一、同事分支更新（main-alpha）

### fix:wpr — 修复为 token 设置模型限制后查询任务失败（401）问题

**文件**：`middleware/distributor.go`、`middleware/distributor_test.go`（新增）

**问题**：token 设置了模型白名单后，轮询视频任务状态（GET `/v1/video/generations/{id}`、`/v1/videos/{id}`）返回 401 错误。

**原因**：分发器对所有请求做模型校验，但视频轮询是 GET 请求，只携带任务 ID，没有请求模型，触发"无可用渠道"。

**修复**：识别视频 fetch 请求（`RelayModeVideoFetchByID`），跳过模型白名单校验；新增 3 个单元测试覆盖视频 fetch / submit / remix 场景。

## 二、官方分支更新（origin/main）

### 2.1 后端新功能

#### Advanced Custom Channel（高级自定义渠道）
- 新增渠道类型：**AdvancedCustom**（编号在 alpha 中为 **60**，官方为 58，因与我们的 AzureVideo/Uptoken 冲突，已重编号）
- 支持配置多条路由规则，每条路由可指定：incoming path、upstream path、协议转换器（Converter）、自定义鉴权
- 支持的协议转换器：
  - Anthropic Messages ↔ OpenAI Chat Completions
  - OpenAI Chat Completions → OpenAI Responses
  - Gemini GenerateContent ↔ OpenAI Chat Completions
- 新增 `relay/channel/advancedcustom/adaptor.go`，约 545 行

#### 订阅计划——降级分组 & 钱包溢出
- `subscription_plans` 表新增字段：`downgrade_group`（降级到期后自动归入的用户组）
- 支持 `wallet_overflow`（订阅到期后余额是否允许超限使用）
- 相关文件：`model/main.go`、`model/subscription.go`、`controller/subscription.go`

#### 路由可靠性管理
- 新增 API：`GET /api/channel/ops`，返回当前重试次数配置（`retry_times`）
- 前端新增渠道亲和性入口

#### LogQuotaData 接口重构
- `LogQuotaData` 函数从多参数签名改为结构体参数 `QuotaDataLogParams`
- 新增字段：`UseGroup`、`TokenID`、`ChannelID`、`NodeName`（数据看板维度更丰富）
- **Alpha 保留**：`model/log.go` 中的 `vendor_id` 合并与 `official_quota` 计算逻辑保持不变

#### Codex 渠道 API 重构
- `GetCodexChannelUsage` 原内联逻辑提取为 `fetchCodexChannelWhamData` 辅助函数
- 新增两个 API：`GetCodexChannelRateLimitResetCredits`、`ResetCodexChannelUsage`

## 三、合并时的冲突处理

| 文件 | 冲突原因 | 处理结果 |
|------|---------|---------|
| `constant/channel.go` | 官方 AdvancedCustom=58 与 Alpha AzureVideo=58 冲突 | **Alpha 优先**：AzureVideo=58、Uptoken=59，AdvancedCustom 重编号为 60 |
| `dto/channel_settings.go` | 官方删除了 BytePlus 字段，Alpha 有 Byteplus Asset API 配置 | **合并两者**：保留 BytePlus 字段，同时引入 AdvancedCustomConfig 新类型 |
| `model/channel_cache.go` | 官方新增 `filterChannelsByRequestPath`，Alpha 有 `GetChannelsByGroupAndModelPrefix` | **合并两者**：两个函数均保留 |
| `model/log.go` | 官方简化了 other 字段处理，Alpha 有 vendor_id 合并和 official_quota 计算 | **Alpha 优先**：保留 vendor_id/official_quota 逻辑；LogQuotaData 调用改用官方结构体 |
| `model/usedata.go` | 官方用标准 insert/update，Alpha 用 rebuildQuotaDataBucketFromLogs | **Alpha 优先**：保留按 logs 精确重算小时桶的逻辑，避免 quota_data 重复累加 |
| `model/main.go` | upgrade_group 字段长度及新增 downgrade_group | **官方优先**：采用 varchar(64) 并新增 downgrade_group 列 |
| `relay/channel/claude/relay-claude.go` | 官方用 json.Unmarshal，Alpha 用 DecodeJson 处理 tool_call 尾部垃圾字符 | **Alpha 优先**：保留容错解析逻辑 |
| `relay/channel/claude/relay_claude_test.go` | Alpha 多了 PDF/文本文件测试用例 | **Alpha 优先**：保留所有测试 |
| `setting/ratio_setting/model_ratio.go` | 官方新增 gpt-5、o3-pro、o4-mini-deep-research 等新模型 | **官方优先**：采用官方扩充版（Alpha 原有模型全部保留） |
| `controller/codex_usage.go` | Codex 函数重构，原内联改为辅助函数 | **官方优先**：采用新结构，内联体重命名适配 |
