# 官方 main 分支更新内容（2026-07-02 至 df01273b9）

本次同步了官方 **78 个提交**（合到安全点 `df01273b9`，后续还有 110 个待分阶段合并，见 [官方合并待办追踪.md](../官方合并待办追踪.md)）。

## 一、计费安全加固（本次最重要）

官方系统性排查了额度计算的**整数溢出**问题。之前如果某次请求的额度算出来超过 int32 上限，会回绕成负数，导致**给用户白送额度**甚至倒扣。

- 新增"饱和转换"：额度超过上限时截断到上限，而不是回绕成负数
- 涉及所有扣费路径：文本、图片、音频、视频任务、实时语音
- 新增 quota saturation 审计事件：一旦发生截断，会在日志 `other` 字段里记一条，管理员能查到
- 请求参数（数量、张数等）新增合法性校验，防止异常大的值传进计费公式

**运维影响**：如果日志里出现 `quota_saturation` 相关字段，说明有请求的计费值异常大，需要检查对应模型的倍率配置。

## 二、SSRF 安全防护

图片/文件下载改用专门的 SSRF 防护 HTTP 客户端，防止用户传一个内网地址进来让服务端去访问（比如探测内网服务、读云厂商元数据接口）。

**我们的调整**：保留了 main-alpha 加的浏览器请求头（很多站点会拒绝 Go 默认 UA 返回 403），和官方的 SSRF 防护叠加使用。
