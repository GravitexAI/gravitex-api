## 一、鉴权 / 并发安全（本次最该关注）

### 1.1 用户更新的并发防覆盖（#5548 backend length validation 一线 + 相关）
官方给 `User.UpdateWithTx` 加了 `authChanged` 检测 + `AuthVersion` 会话失效 + 扩大 `Omit` 列表，避免"用读取时刻的陈旧快照覆盖并发发生的额度扣减 / aff 变更 / access_token 轮换"。

**我们的处理**：**只吸收并发防覆盖的 Omit 扩展**（`access_token` / `aff_count` / `aff_quota` / `aff_history` 加入 Omit），**去掉 `auth_version` 及 `IncrementUserAuthVersionWithTx` / `AuthVersion` 字段**——那套是官方 `31d70fca3` 无状态会话方案的一部分，fork 已用 A2 鉴权（`login_session`）+ RuoYi SSO 替代，**整体拒绝**。详见[防丢清单 §5.3 / §5.7](../main-alpha_独有功能清单.md) 与本批新增的 AuthVersion 拒绝说明。

### 1.2 access-token 路由限流（1da23d6b3）
官方给 `/api/user/token`（生成 access token）等路由加了 `UserCriticalRateLimit` + `DisableCache`。已吸收（`router/api-router.go` 的 `/token` 路由）。

### 1.3 user-quota / token-quota 的 Redis 原子预留（quota_reserve.go）
官方把额度预留改为 Redis Lua 原子脚本（`TryReserveUserQuota` / `TryReserveTokenQuota`），并用 `CacheSchema` 版本号门禁避免读到旧格式缓存。批量模式下这条**能防止降级读未刷新的过期 DB 余额而超扣**。

**我们的处理（关键集成）**：官方这套依赖 `user_auth_cache.go`（AuthVersion 机制，fork 已拒绝）来写入 `CacheSchema`。为让预留在 fork 下正常工作又不引入 AuthVersion：
- 在 `UserBase` 加 `CacheSchema` 字段、`User.ToBaseUser()` 里置为 `userCacheSchemaVersion=2`（`model/user_cache.go` / `model/user.go`），使 `populateUserCache` 写入的缓存 hash 带上 schema；
- **`TryReserveUserQuota` 的水合改为同步**（`GetUserById` + `populateUserCache`）——fork 的 `GetUserCache` 是 `gopool.Go` 异步 populate，而预留的"水合后立即重试"需要缓存立即可见，否则重试仍 miss、降级到批量模式下过期的 DB 余额。详见[防丢清单 §7.11.16](../main-alpha_独有功能清单.md)。

### 1.4 OAuth 绑定加固（116255f07 / d7992672a / e78e1db1e）
绑定响应字段对齐、避免绑定时用完整快照覆盖并发的封禁/降权（改走列级 `UpdateUserBindColumn`）、外部 window.opener 不再误判为绑定流。已吸收；但官方的 `ConsumeAuthFlow` 流程令牌校验（`AuthFlow` 机制）fork 不存在，`controller/oauth.go` 绑定入口改用 fork 的 session 机制取当前用户 + 保留官方安全的列级更新尾部。
