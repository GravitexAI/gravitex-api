## 二、官方新增或更新内容

以下内容均来自官方 `main` 分支在共同祖先 `2d8e50bf` 之后的提交，包括任务插件、协议转换、日志权限、计费完整性、数据库兼容、鉴权安全和前端更新。

### 1. 任务插件体系

官方 main 增加了基于 JavaScript 的任务插件运行时、插件注册、版本管理、协议处理、调试接口和插件任务路由，并补充了任务插件相关数据库模型、管理接口和前端页面。

该能力与 Alpha 原有的 Suno、Lyria、Seedance、Kling、Vidu、Sora、Gemini 等原生任务适配器并存。原生任务不能因为插件体系存在而删除或改走插件路径。

### 2. 任务轮询和任务状态

官方增加了通用任务轮询、插件任务状态、任务执行快照、失败次数记录、任务产物及后台任务状态处理。

Alpha 原有的本地异步任务、视频任务预扣费、退款、差额结算和平台专属状态转换继续保留。任务插件字段仅作为新增能力，不替换 Alpha 的历史任务数据格式。

### 3. 协议转换与工具调用

官方补充了 OpenAI Responses、Claude、Gemini 之间的协议转换，以及 reasoning、工具调用、工具结果、引用和服务端工具用量字段。

合并时保留 Alpha 的原生 Claude 请求体、Gemini Omni 多模态处理、Google Search 识别和特殊模型请求逻辑。协议转换新增字段必须避免改变 Alpha 的上游请求过滤和计费结果。

### 4. 日志和用量审计

官方增加了日志 Other 字段的权限分层、管理员/root 投影、任务插件身份快照、用量字段和部分日志展示能力。

Alpha 原有的 ByteHouse/ClickHouse 日志、Snowflake ID、请求 ID、工具计费信息、官方成本和 quota stream 字段继续保留。普通用户日志不得看到管理员审计信息或内部成本信息。

### 5. 模型定价和工具计费

官方增加了更结构化的用量定价 schema、定价示例、工具损耗策略和动态计费表达式支持。

Alpha 原有的以下计费逻辑继续优先：

- `lyria-3-pro-preview` 的本地异步及任务计费；
- `gemini-3-pro-image` 的图片输出、文本输出和 Google Search 工具计费；
- `dola-seedream-5-0-pro-260628` 的实际输出图片数量、分辨率层级和 `layer_decomposition` 计费；
- 图片 `n` 参数不重复计算；
- 预扣费、结算、退款和额度饱和保护。

### 6. 鉴权和安全配置

官方增加了可选的密码登录加密、可信代理配置和部分权限同步能力。

Alpha 的 RuoYi JWT、A2 登录会话、Cookie 登录、平台隔离和企业账号逻辑继续保留。密码加密默认不改变现有登录行为，启用前需要单独评估部署配置和旧密码兼容性。

### 7. 数据库和依赖

官方增加了任务插件、登录加密、权限及任务状态相关模型和迁移，并更新了协议转换依赖。

本次保留 Alpha 的 SQLite、MySQL、PostgreSQL 和独立日志库分支处理。数据库迁移、字段类型、JSON 存储和启动幂等性仍需在三种数据库实例上分别验证，不能仅以 Go 编译通过作为数据库兼容结论。

### 8. 前端

官方增加了任务插件管理、任务详情、用量日志信息和定价 schema 相关页面及多语言资源。

Alpha 的 `web/default`、`web/classic` 双前端结构和 embed 构建方式继续保留。官方新增页面需要映射到实际使用的前端 workspace，不能删除 classic 或将两个前端直接摊平。

## 三、合并后的验证边界

- relaykit 独立构建：已通过。
- `relay/helper`：已通过测试。
- 根项目关键模块：生产代码接口已继续调整，但旧 Alpha 测试和官方新增测试仍存在任务快照、日志类型及轮询 adaptor 签名差异，尚未完成全量测试通过。
- 三数据库新鲜库、升级库、重复启动和独立日志库：本次尚未执行完整矩阵验证。

## 四、后续注意事项

1. 后续再次合并官方 main 时，先检查任务插件是否覆盖原生任务适配器。
2. 检查工具用量是否同时进入预扣费、结算、退款和日志审计链路。
3. 对上述三个特殊模型优先执行定向回归测试。
4. 任何日志 Other 类型调整都必须同时兼容 Alpha 的历史 map 数据和官方新的权限投影。
5. 未完成测试和三数据库验证前，不应将该分支直接作为生产发布版本。
