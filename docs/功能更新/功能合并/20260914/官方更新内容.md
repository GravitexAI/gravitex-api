# main 分支官方更新内容（2026-09-14）

> 本文记录官方 `main` 从上次归档基线 `3a9f41ee8` 到 `7fd063819` 的 74 个提交（2026-09-05 至 2026-09-13）。这是待合入 `main-alpha-merge` 的功能说明，不表示这些代码已经进入 `main-alpha`，也不表示已完成构建、数据库或生产验证。

## 一、账户安全与登录

官方新增了 Access Token 的管理与审计记录，账户绑定、改密码、删除账号等敏感操作改为需要与会话和动作绑定的验证证明，并统一了登录验证流程。Telegram 登录迁移到统一 OAuth；Passkey 支持在受控配置下使用多个 RP ID，并补充网站域名配置和兼容域名恢复逻辑。

对用户而言，账户安全页面、验证流程和登录方式更完整；对运维而言，需要按部署域名配置 Passkey，不能把多 RP ID 当作不受限制的跨站登录能力。

## 二、模型、供应商与渠道管理

官方重构模型与供应商管理，补充模型可见性、元数据、价格配置和同步能力；后台可编辑渠道插件扩展，选择供应商和模型时可展示插件信息与图标，内置渠道 Base URL 以占位提示展示。多 key 渠道可以编辑选择策略，渠道测试、模型列表和高级自定义路由也有相应修复。

模型广场和模型定价界面同步调整，包含供应商关联、价格同步、模型删除/筛选和更清晰的配置入口。火山方舟模型列表地址、Sora 查询字段、Alibaba Wan 协议和用量计算也得到修正；新增 Wan 3.0 一体化视频模型支持。

## 三、表达式计费与用量展示（仅作 Alpha 的增量输入）

> **主从规则：`main-alpha` 的计费实现是唯一基线，官方 `main` 不是替代方案。** 不得以官方版本覆盖 Alpha 的视频结算、图片按张分档、原生任务适配器或 `service`/`relay` 中既有计费闭环。以下官方能力只有在保持 Alpha 的验证、预扣费、实际结算、退款、渠道成本快照和日志审计后，才能按功能点吸收。

官方继续扩展表达式计费：支持固定“每请求”价格、按时段的价格规则、图片数量及缓存相关变量，为 GPT Image 提供默认表达式，并把旧的传统价格转换为可审核的表达式草稿。后台可预览表达式结果、对比草稿后再应用，模型卡片、用量详情和日志展示也配合更新；站点货币可用于定价编辑。

同时，图片数量在预扣费前增加校验，避免不受约束的数量参与计费。该项是请求校验与计费安全改进，不应被理解为已覆盖 Alpha 的全部图片、视频或第三方任务结算逻辑，更不能替换 Alpha 的图片 `n` 防重复计算、Seedream 实际输出张数/尺寸分档、视频 CAS 结算、Lyria/Gemini 专项计费和配额饱和审计。

## 四、任务插件与异步任务

官方增强 JavaScript 任务插件：插件元数据支持图标、网站、更新记录和本地化 changelog，管理页与市场展示增加能力说明、完整性检查、模型列表和端点信息。插件任务支持更完整的流式提交和模型定价，内置插件的别名处理、禁用覆盖插件时的 factory 行为和 JSON 状态的非法 UTF-8 兼容性也得到修复。

这些更新提升任务插件的配置和可观测性，但不自动覆盖任何 fork 的原生任务适配器、轮询、预扣费或结算流程。

## 五、Relay、协议兼容与性能

官方调整了 OpenAI Chat 的模型能力应用方式，保留 reasoning effort，支持显式 `@` 模型修饰符和规范化计费身份；Kimi K3 动态工具加载消息、Sora 查询字段、Alibaba Wan 协议与用量、模型健康条的小时成功率均有修复。relaykit 继续保留缓存输入 token 的细分用量，并将 JSON 编解码转为可由宿主注入的实现，便于模块独立运行。

公共层对 `RawMessage` 深拷贝进行批量优化，减少请求副本的重复处理。此类调整需要继续遵守根项目的 JSON 包装约束与 relaykit 独立构建约束。

## 六、审计、日志、兑换与后台体验

官方补全 Token 与额度变更的操作记录，新增审计日志查看能力，并改进 API Key 配额、用户额度、用量日志移动端布局和可搜索的用户组筛选。兑换码支持批量删除及可选文件导出，服务端错误提示、状态请求去重、抽屉交互和表格单元格展示也得到统一。

后台新增管理员更新提醒；这是一项界面和更新信息能力，不等同于自动下载、自动部署或自动合并代码。

## 七、数据库兼容与迁移

官方为账户安全、审计、模型/供应商、定价和任务插件增加或调整了模型与迁移逻辑，并处理 options 表主键重建、prefill group 旧索引重命名、遗留约束和 scoped policy 的兼容，以及重复启动时不必要的 schema migration。

这些变更尚未在 Alpha 整合分支执行数据库验证。实际合入后必须在 SQLite、MySQL、PostgreSQL 上分别验证新库、从旧版本升级、重复启动和独立日志库场景；Go 编译或单一数据库测试不能替代该矩阵。

## 八、前端与运维界面

官方统一渠道配置、模型和系统设置编辑器，提供可折叠的移动端表格过滤器，调整模型定价为单一可滚动区域，并优化价格卡片、配额详情、通知与状态查询。任务插件、模型、定价、使用日志、账户安全等页面均新增测试和多语言资源。

本仓库的 Alpha 分支仍保留 `web/default` 与 `web/classic` 双前端。合入时应按实际页面和 API 契约选择性迁移，不可把官方 `web/` 根应用整体覆盖到 workspace 根。

## 九、合并边界

### 计费优先级

所有计费相关冲突先保留 `main-alpha` 行为，再评估官方单个能力是否可安全增量接入。尤其不得整文件接受官方的 `service/task_billing.go`、`service/text_quota.go`、`relay/image_handler.go`、`relay/helper/price.go`、`relay/helper/valid_request.go`、`relay/relay_task.go`，或以官方任务插件替换 Alpha 的原生视频/异步任务链路。官方计费变更必须逐项证明不会绕开或重复执行 Alpha 的预扣费、结算、退款和审计。

本批功能的具体防丢与验证要求已写入 [main-alpha 独有功能清单](../main-alpha_独有功能清单.md) 的“零点一”和第九节。实际冲突处理、接受或拒绝的差异、执行过的测试以及数据库验证结果，应在完成 `main-alpha-merge` 后另写 `合并调整说明.md`；在那之前，本文件仅是官方输入范围的功能归档。
