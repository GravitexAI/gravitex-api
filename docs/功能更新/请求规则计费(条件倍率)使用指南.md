# 请求规则计费（条件倍率）使用指南

> 位置：**模型定价 → 编辑模型定价 → 计费模式选「阶梯计费」→ 规则计费**
> 后端：`pkg/billingexpr`（详细设计见 `pkg/billingexpr/expr.md`）
> 来源：官方 `feat(billing): highlight matched conditional multipliers in logs (#6561)`

---

## 一、这是什么

**请求规则计费**是「阶梯计费」之上的一层**条件倍率**：给一条模型定价追加若干「规则」，**当请求满足规则条件时，把最终价格乘以一个倍率**。

一句话核心（就是编辑器里的那段说明）：

> **条件满足时，最终价格乘以 X；多条命中的倍率会相乘；小于 1 的值为折扣。**

- 倍率 `> 1` → **加价**（例如高优先级/加速模式收 2 倍）
- 倍率 `< 1` → **折扣**（例如 `0.5` = 打 5 折）
- 倍率 `= 1` → 不影响
- **多条规则同时命中 → 各自倍率连乘**（例如命中 `0.5` 和 `0.8` → 最终 ×0.4）

> 它**只改变最终价格的乘数**，不改阶梯档位本身的计费逻辑。基础价（阶梯表达式算出的价）× 命中的所有规则倍率 = 实际扣费。

**典型场景**：**时段计费 / 波峰波谷计费**——按请求发生的**时间**给不同折扣，正是为 DeepSeek 这类「错峰时段打折」定价做的（见下方第四节实例）。

---

## 二、规则由什么组成

每条「规则组」= **一组条件（同组内为「与」关系，全部满足才算命中）+ 一个倍率**。

### 条件来源（3 类）

| 来源 | 说明 | 底层函数 |
|---|---|---|
| **请求参数** | 读请求体里的 JSON 字段（gjson 路径） | `param("路径")` |
| **请求头** | 读某个请求头的值 | `header("Header-Name")` |
| **时段** | 按当前时间判断（含时区），做时段计费 | `hour/minute/weekday/month/day("时区")` |

### 匹配方式

- **参数/请求头**：等于 / 包含 / 存在
- **时段/数值**：等于 / 大于 / 大于等于 / 小于 / 小于等于 / **跨夜范围**

### 时段函数（时区可选）

| 函数 | 含义 | 取值 |
|---|---|---|
| `hour(tz)` | 当前小时 | 0–23 |
| `minute(tz)` | 当前分钟 | 0–59 |
| `weekday(tz)` | 星期 | 0=周日 … 6=周六 |
| `month(tz)` | 月 | 1–12 |
| `day(tz)` | 日 | 1–31 |

时区从下拉选，常用 `Asia/Shanghai`（UTC+8 北京）。⚠️ **时段判定按选定时区，不是服务器本地时间**——务必选对时区，否则波峰波谷会错位。

## 三、在界面里怎么配（阶梯计费 → 规则计费）

1. 编辑模型定价，**计费模式**选 **阶梯计费**。
2. 先配好上半部分的**阶梯/基础表达式**（基础价，见 [`阶梯计费表达式使用指南.md`](阶梯计费表达式使用指南.md)）。
3. 下半部分 **规则计费** → **新增规则组**：
   - 选**条件来源**（时段 / 请求参数 / 请求头）；
   - 时段类：选**时段函数**（如 `hour`）+ **时区** + **匹配方式** + 值；
   - 填**倍率**（如 `0.5` 折扣、`2` 加价）；
   - 需要「与」条件时，在同一组里**追加条件**（全部满足才命中）。
4. 多个折扣/加价 → **新增多个规则组**（命中的组倍率**连乘**）。
5. 保存（classic 前端会弹 OperLog 确认框记录改动）。

前后端会把「基础表达式」和「规则表达式」用分隔符 `|||` 合并成一条最终 `billing_expr` 存库。

## 四、实例：DeepSeek 波峰波谷（错峰折扣）

DeepSeek 官方对**错峰时段**给折扣（北京时间 **00:30–08:30**，具体费率以官方为准）：
👉 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing/>
（例如 `deepseek-chat` 错峰约 5 折、`deepseek-reasoner` 错峰更低——以官方页面实时费率为准。）

### 做法 A：界面简单配（按整点近似）

给 `deepseek-chat` 加一条规则组：

- 条件：**时段** `hour`，时区 `Asia/Shanghai`，**小于** `8`
- 倍率：`0.5`

→ 表示「北京时间 00:00–07:59 全价 ×0.5」。简单但**边界是整点**，与官方 00:30/08:30 的半点边界有约半小时误差。

### 做法 B：精确到半点（高级表达式，直接写规则表达式）

要精确覆盖 **00:30–08:30**，用 `hour*60+minute`（分钟数）表达，手写规则表达式：

```
(hour("Asia/Shanghai") * 60 + minute("Asia/Shanghai") >= 30
 && hour("Asia/Shanghai") * 60 + minute("Asia/Shanghai") < 510 ? 0.5 : 1)
```

- `30` = 00:30，`510` = 08:30（8×60+30）。
- `deepseek-reasoner` 把 `0.5` 换成其错峰倍率即可。

### 存库后的最终表达式长这样

```
tier("base", p * 1 + c * 2)|||(hour("Asia/Shanghai") * 60 + minute("Asia/Shanghai") >= 30 && hour("Asia/Shanghai") * 60 + minute("Asia/Shanghai") < 510 ? 0.5 : 1)
```

`|||` 前是基础阶梯价，后面是错峰折扣规则；命中错峰时段时最终价 ×0.5。

## 五、实例（详解）：工作日高峰 / 空闲分时计费

**需求**：空闲时段价格 = 高峰时段价格的一半。
**高峰**（全价）：北京时间**周一至周五** 且 **9:00–12:00** 或 **14:00–18:00**；
**空闲**（半价 ×0.5）：其余所有时间（含周末、以及工作日的凌晨/12–14 点/18 点后）。

### 5.1 逻辑拆解

| 维度 | 表达 | 说明 |
|---|---|---|
| 工作日 | `weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5` | 周一=1 … 周五=5（0=周日、6=周六） |
| 上午窗 | `hour("Asia/Shanghai") >= 9 && hour("Asia/Shanghai") < 12` | 覆盖 09:00:00–11:59:59，**到 12:00 整结束** |
| 下午窗 | `hour("Asia/Shanghai") >= 14 && hour("Asia/Shanghai") < 18` | 覆盖 14:00:00–17:59:59，**到 18:00 整结束** |
| **高峰** | 工作日 **且**（上午窗 **或** 下午窗） | 两窗是「或」 |
| **空闲** | **非**高峰 | 打 5 折的时段 |

> ⚠️ 边界用「小于」而非「小于等于」：`hour < 12` 表示 12:00 整已算空闲；若想让 12:00 整仍算高峰，用 `hour <= 12`（但那样 12:00–12:59 整段都算高峰，通常不是你要的）。时区**务必选 `Asia/Shanghai`**，否则高峰时段会整体错位。

### 5.2 方案 A（推荐，最直观）：基础价 = 高峰全价，空闲时 ×0.5

**基础表达式**（上半部分）填**高峰（全价）**的阶梯价，例如：

```
tier("base", p * 1 + c * 2)
```

**规则表达式**（下半部分，或直接手写）填这一条——「非高峰即空闲，打 5 折」：

```
(!(weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5 && ((hour("Asia/Shanghai") >= 9 && hour("Asia/Shanghai") < 12) || (hour("Asia/Shanghai") >= 14 && hour("Asia/Shanghai") < 18))) ? 0.5 : 1)
```

- `!(高峰条件)` 为真（= 空闲）→ ×0.5；高峰时 → ×1（全价）。
- 保存后系统用 `|||` 把两段合成一条存库，最终长这样：

```
tier("base", p * 1 + c * 2)|||(!(weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5 && ((hour("Asia/Shanghai") >= 9 && hour("Asia/Shanghai") < 12) || (hour("Asia/Shanghai") >= 14 && hour("Asia/Shanghai") < 18))) ? 0.5 : 1)
```

> 高峰逻辑里同时有「或」（两个时间窗）和「非」（空闲=非高峰），界面的规则组（组内只能「与」）表达不出来，所以方案 A **建议直接手写这条规则表达式**。

### 5.3 方案 B（纯界面点选，不手写）：基础价 = 空闲半价，两个规则组高峰 ×2

反过来配：把**基础价填成空闲（半价）**，高峰时 ×2 补回全价。因为两个高峰窗**互不重叠**，任一命中就 ×2，都不命中（空闲）就是 ×1。

1. **基础表达式**填**空闲（半价）**的阶梯价（即高峰价的一半），例如高峰若是 `p*1+c*2`，这里填 `tier("base", p * 0.5 + c * 1)`。
2. **规则组 1（高峰·上午）**——组内 4 个「与」条件，倍率 **2**：
   | 条件来源 | 时段函数 | 时区 | 匹配 | 值 |
   |---|---|---|---|---|
   | 时段 | weekday | Asia/Shanghai | 大于等于 | 1 |
   | 时段 | weekday | Asia/Shanghai | 小于等于 | 5 |
   | 时段 | hour | Asia/Shanghai | 大于等于 | 9 |
   | 时段 | hour | Asia/Shanghai | 小于 | 12 |
3. **规则组 2（高峰·下午）**——同上，把 hour 两条换成 **大于等于 14**、**小于 18**，倍率 **2**。

命中效果：工作日 09–12 → 组1 命中 ×2 = 全价；工作日 14–18 → 组2 命中 ×2 = 全价；其余 → 无命中 ×1 = 半价。

### 5.4 两种方案对比

| | 基础价填 | 规则 | 是否手写 |
|---|---|---|---|
| **方案 A**（推荐） | 高峰**全价** | 空闲 ×0.5（1 条，含「非/或」） | 需手写规则表达式 |
| **方案 B** | 空闲**半价** | 高峰 ×2（2 个规则组，纯「与」条件） | 全程点界面 |

两者计费结果完全一致。A 更符合直觉（基础价 = 牌价/高峰价，账单折扣一目了然）；B 全程界面点选、无需懂表达式。

### 5.5 自测建议

配好后在账单/用量日志里核对命中情况（`other.request_rules`，命中会高亮）：
- 工作日 10:00 的请求：方案 A 应**无**折扣规则命中（全价）；方案 B 应命中「高峰·上午」组（×2）。
- 周六 10:00 或工作日 22:00 的请求：方案 A 应命中空闲折扣（×0.5）；方案 B 应无高峰组命中（半价）。

## 六、其它常见规则示例

```text
# 跨午夜的夜间折扣（22:00–06:00 打 7 折）——用「跨夜范围」
(hour("Asia/Shanghai") >= 22 || hour("Asia/Shanghai") < 6 ? 0.7 : 1)

# 加速/高优先级请求加价 2 倍（按请求参数）
(param("service_tier") == "fast" ? 2 : 1)

# 按请求头命中加价
(header("anthropic-beta") has "fast-mode" ? 6 : 1)

# 周末折扣 8 折（周六/周日）
(weekday("Asia/Shanghai") == 6 || weekday("Asia/Shanghai") == 0 ? 0.8 : 1)
```

> **跨夜范围** = `时段 >= 起点 || 时段 < 终点`，**仅用于跨越午夜**的窗口（起点 > 终点，如 22→6）。同一天内的窗口（如 01–08）请用「大于等于 + 小于」两个条件的**与**组合，别用跨夜范围（会恒为真）。

## 七、账单里怎么看（命中高亮）

- 每次请求结算时，引擎会把**实际命中的规则**记进消费日志 `other.request_rules`：
  ```json
  { "request_rules": [ { "cond": "hour(\"Asia/Shanghai\") ...", "multiplier": 0.5, "matched": true } ] }
  ```
- 用量日志 UI 直接按这份列表渲染，**命中的规则会高亮**，未命中的规则也会列出（`matched:false`），方便核对「这单为什么打了折/加了价」。

---

## 八、注意事项（易踩坑）

1. **只有形如 `<条件> ? <数字> : 1` 且条件引用请求探针**（param/header/hour/minute/weekday/month/day）的规则才会被**追踪与高亮**；兜底分支**必须是 `1`**。写成 `? 2 : 1.5` 这类会照常参与计算但**不会**在账单里被标为规则。
2. **时区**决定波峰波谷判定，选错时区 = 折扣时段错位。
3. **多条命中连乘**：叠加多个折扣要算清总倍率（0.5 × 0.8 = 0.4），别叠出意外低价。
4. **`< 1` 才是折扣**；填 `50`（想表示 5 折）是**加价 50 倍**，别填错。
5. 基础阶梯价的**档位条件建议用 `len`**（完整输入长度）而非 `p`，避免缓存命中拉低 `p` 误判档位（见 `expr.md`）。
6. 改定价属审计项，保存时按 OperLog 流程确认（模型价格类）。
