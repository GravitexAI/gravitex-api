# 阶梯计费表达式使用指南

## 概述

阶梯计费表达式系统（Tiered Billing Expression）是一套基于表达式语言的动态计费引擎。核心理念是 **"一个表达式，一个真相"** — 一个表达式字符串完整描述一个模型的全部计费规则，取代分散的倍率表和价格配置。

**适用场景：**
- 按上下文长度分档定价（如 Claude 标准/长上下文模式）
- 按 token 类型分维度定价（输入/输出/缓存/图片/音频各自不同价格）
- 按请求条件动态加价（如特定 header、请求参数、时间段）
- 多模态模型复杂定价

---

## 一、快速入门

### 1.1 开启阶梯计费

进入 **系统设置 → 分组与模型定价设置**，在模型定价编辑器中：

1. 选择目标模型
2. 将计费模式切换为 **"阶梯计费"**（`tiered_expr`）
3. 使用可视化编辑器配置价格档位，或直接编写表达式
4. 保存（系统会自动做语法检查和冒烟测试）

### 1.2 最简单的表达式

```
tier("base", p * 2.5 + c * 15)
```

含义：输入 token $2.5/1M，输出 token $15/1M。所有系数均为 **$/1M tokens** 单位。

## 二、表达式语言参考

### 2.1 Token 变量

表达式引擎提供 10 个 token 维度变量：

#### 输入侧

| 变量 | 类型 | 含义 | 说明 |
|------|------|------|------|
| `p` | float64 | 输入 token | 自动排除已单独定价的子类（见 2.4 节） |
| `len` | float64 | 总输入上下文长度 | 用于分档条件判断，不受排除影响 |
| `cr` | float64 | 缓存读取（命中）token | |
| `cc` | float64 | 缓存创建 token（5 分钟 TTL） | Claude 为 5 分钟缓存，通用缓存 |
| `cc1h` | float64 | 缓存创建 token（1 小时 TTL） | 仅 Claude |
| `img` | float64 | 图片输入 token | |
| `ai` | float64 | 音频输入 token | |

#### 输出侧

| 变量 | 类型 | 含义 | 说明 |
|------|------|------|------|
| `c` | float64 | 输出 token | 自动排除已单独定价的子类 |
| `img_o` | float64 | 图片输出 token | |
| `ao` | float64 | 音频输出 token | |

### 2.2 内置函数

#### 计费函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `tier(name, cost)` | `(string, float64) → float64` | 标记当前匹配的定价档位名称，返回 cost 值不变。**每个计费分支必须用 tier() 包裹。** |

#### 请求上下文函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `header(key)` | `(string) → string` | 读取请求 header（key 不区分大小写），未找到返回 `""` |
| `param(path)` | `(string) → any` | 读取请求体 JSON 路径（使用 gjson 语法），未找到返回 `nil` |
| `has(source, substr)` | `(any, string) → bool` | 判断 source（转为字符串后）是否包含 substr |

#### 时间函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `hour(tz)` | `(string) → int` | 当前小时（0-23），tz 为 IANA 时区名（如 `"Asia/Shanghai"`），空字符串为 UTC |
| `minute(tz)` | `(string) → int` | 当前分钟（0-59） |
| `weekday(tz)` | `(string) → int` | 星期几（0=周日, 6=周六） |
| `month(tz)` | `(string) → int` | 月份（1-12） |
| `day(tz)` | `(string) → int` | 日期（1-31） |

#### 数学函数

| 函数 | 说明 |
|------|------|
| `max(a, b)` | 取较大值 |
| `min(a, b)` | 取较小值 |
| `abs(x)` | 绝对值 |
| `ceil(x)` | 向上取整 |
| `floor(x)` | 向下取整 |

### 2.3 额度转换公式

表达式系数为 **$/1M tokens** 的真实价格。系统将表达式输出转换为内部额度单位：

```
quotaBeforeGroup = exprOutput / 1,000,000 × QuotaPerUnit
quotaAfterGroup  = Round(quotaBeforeGroup × groupRatio)
```

其中 `QuotaPerUnit = 500,000`。

**示例：** 如果表达式输出 `p * 3 + c * 15`，输入 1000 token + 输出 500 token：
```
exprOutput = 1000 × 3 + 500 × 15 = 10,500
quotaBeforeGroup = 10,500 / 1,000,000 × 500,000 = 5,250
```
若 groupRatio = 1.0，最终额度 = 5,250。

### 2.4 P/C 自动排除规则

**核心原则：** 如果表达式中使用了某个子类变量（如 `cr`），系统会自动从 `p` 中减去对应的 token 数量，避免重复计费。

**判定方式：** 编译时通过 AST 分析检测表达式引用了哪些变量。

| 子类变量 | 使用时从 `p` 减去 | 使用时从 `c` 减去 |
|---------|------------------|------------------|
| `cr` | 缓存读取 token | — |
| `cc` | 缓存创建 token (5m) | — |
| `cc1h` | 缓存创建 token (1h) | — |
| `img` | 图片输入 token | — |
| `ai` | 音频输入 token | — |
| `img_o` | — | 图片输出 token |
| `ao` | — | 音频输出 token |

**举例说明：**

假设上游返回：`prompt_tokens = 1000`（其中 200 缓存读取、100 图片输入）

| 表达式 | `p` 实际值 | 原因 |
|--------|-----------|------|
| `p * 3 + c * 15` | 1000 | 未使用 `cr`/`img`，全部 token 在 `p` 中 |
| `p * 3 + c * 15 + cr * 0.3` | 800 | 使用了 `cr`，减去 200 |
| `p * 3 + c * 15 + cr * 0.3 + img * 2` | 700 | 使用了 `cr` 和 `img`，减去 200+100 |

**注意：**
- `len` 变量**永远不受排除影响**，始终反映完整输入长度
- Claude 格式 API 的 `input_tokens` 已是纯文本 token，不需要排除处理
- `p` 和 `c` 的最终值不会低于 0

### 2.5 表达式版本

表达式支持版本前缀 `v1:`，不写则默认 v1。版本控制以下行为：
- 编译环境（可用变量和函数集）
- Token 归一化逻辑
- 额度转换公式

目前仅有 v1 版本。

## 三、表达式编写示例

### 3.1 扁平定价（单一档位）

```
tier("base", p * 2.5 + c * 15 + cr * 0.25)
```

### 3.2 多档阶梯定价

按输入上下文长度分档（使用 `len` 做条件判断）：

```
len <= 200000
  ? tier("standard", p * 3 + c * 15 + cr * 0.3 + cc * 3.75 + cc1h * 6)
  : tier("long_context", p * 6 + c * 22.5 + cr * 0.6 + cc * 7.5 + cc1h * 12)
```

### 3.3 多模态模型（含图片和音频）

```
tier("base", p * 0.43 + c * 3.06 + img * 0.78 + ai * 3.81 + ao * 15.11)
```

### 3.4 带图片输出的模型

```
tier("base", p * 2 + c * 8 + img * 2.5 + img_o * 12)
```

### 3.5 带请求条件乘数

对特定请求条件（如 header 包含某个值）加价：

```
(tier("base", p * 5 + c * 25)) * (header("anthropic-beta") != "" ? 6 : 1)
```

含义：基础价格为 `p * 5 + c * 25`；当请求 header 包含 `anthropic-beta` 时，费用乘以 6 倍。

### 3.6 基于时间段的定价

```
hour("Asia/Shanghai") >= 0 && hour("Asia/Shanghai") < 6
  ? tier("off-peak", p * 2 + c * 10)
  : tier("peak", p * 3 + c * 15)
```

### 3.7 基于请求参数的定价

```
param("service_tier") == "fast"
  ? tier("fast", p * 6 + c * 30)
  : tier("standard", p * 3 + c * 15)
```

## 四、系统数据流

完整的请求生命周期：

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: 管理员保存表达式                                   │
│  ┌──────────────────────┐                                │
│  │ 前端 TieredPricing   │                                │
│  │ Editor 可视化编辑     │                                │
│  └──────────┬───────────┘                                │
│             │ PUT /api/option/                            │
│             ▼                                            │
│  ┌──────────────────────┐                                │
│  │ SmokeTestExpr()      │  编译检查 + 8 组测试向量验证       │
│  │ (4 token向量 × 2 请求) │  所有结果必须 >= 0              │
│  └──────────┬───────────┘                                │
│             │ 通过                                        │
│             ▼                                            │
│  billing_setting.billing_mode["model"] = "tiered_expr"   │
│  billing_setting.billing_expr["model"] = "表达式字符串"     │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Step 2: 请求预扣费                                       │
│                                                          │
│  modelPriceHelperTiered()                                │
│   ├─ 加载表达式: GetBillingExpr(modelName)                │
│   ├─ 构建请求上下文: ResolveIncomingBillingExprRequestInput │
│   ├─ 运行表达式（使用预估 token 数）                        │
│   ├─ 额度转换: exprOutput / 1M × QuotaPerUnit × groupRatio│
│   ├─ 冻结 BillingSnapshot（表达式、hash、分组倍率、预估值） │
│   └─ 存储到 RelayInfo.TieredBillingSnapshot               │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Step 3: 上游 API 调用（表达式系统不参与）                   │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Step 4: 结算（实际计费）                                   │
│                                                          │
│  TryTieredSettle(relayInfo, tokenParams)                 │
│   ├─ 获取 usedVars（AST 分析缓存）                        │
│   ├─ BuildTieredTokenParams：                            │
│   │   ├─ 从 Usage 提取实际 token 数                       │
│   │   ├─ 计算 len（Claude: input+cache; GPT: prompt）     │
│   │   └─ 根据 usedVars 执行 P/C 自动排除                  │
│   ├─ ComputeTieredQuotaWithRequest：                     │
│   │   ├─ 用冻结的表达式（SHA-256 缓存命中，无需重编译）      │
│   │   ├─ 用实际 token + 冻结的请求上下文重新运行            │
│   │   ├─ quotaConversion → × GroupRatio → QuotaRound      │
│   │   └─ 检测档位漂移: crossed = 实际档位 ≠ 预估档位        │
│   └─ 返回 TieredResult                                   │
│                                                          │
│  若表达式运行失败 → 回退到预扣费额度                         │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Step 5: 日志记录                                         │
│                                                          │
│  InjectTieredBillingInfo(other, relayInfo, tieredResult)  │
│   ├─ other["billing_mode"] = "tiered_expr"               │
│   ├─ other["expr_b64"] = base64(表达式字符串)              │
│   └─ other["matched_tier"] = "standard" (匹配的档位名)    │
│                                                          │
│  前端检测 billing_mode 展示动态计费详情                      │
└─────────────────────────────────────────────────────────┘
```

## 五、存储配置

### 5.1 Option 表键名

| DB 键 | 内容 | 示例值 |
|-------|------|--------|
| `billing_setting.billing_mode` | 模型 → 计费模式映射 | `{"claude-sonnet-4": "tiered_expr"}` |
| `billing_setting.billing_expr` | 模型 → 表达式字符串映射 | `{"claude-sonnet-4": "len <= 200000 ? tier(...)..."}` |

未配置的模型默认使用 `"ratio"`（传统倍率模式）。

### 5.2 BillingSnapshot（冻结快照）

在预扣费阶段冻结，用于结算时确保表达式一致性：

```go
type BillingSnapshot struct {
    BillingMode               string   // "tiered_expr"
    ModelName                 string   // 原始模型名
    ExprString                string   // 完整表达式字符串
    ExprHash                  string   // SHA-256 hex
    GroupRatio                float64  // 请求时的分组倍率
    EstimatedPromptTokens     int      // 预估输入 token
    EstimatedCompletionTokens int      // 预估输出 token
    EstimatedQuotaBeforeGroup float64  // 预估额度（分组前）
    EstimatedQuotaAfterGroup  int      // 预估额度（分组后）
    EstimatedTier             string   // 预估匹配档位
    QuotaPerUnit              float64  // 500000
    ExprVersion               int      // 1
}
```

## 六、冒烟测试

保存表达式前，系统自动运行冒烟测试。使用以下测试矩阵（4 组 token × 2 组请求 = 8 次执行）：

**Token 向量：**

| P | C | Len |
|---|---|-----|
| 0 | 0 | 0 |
| 1,000 | 1,000 | 1,000 |
| 100,000 | 100,000 | 100,000 |
| 1,000,000 | 1,000,000 | 1,000,000 |

**请求输入：**
1. 空请求 `{}`
2. 带 header `{"anthropic-beta": "fast-mode-2026-02-01"}` + 带 body `{"service_tier":"fast",...}`

**验证规则：**
- 所有 8 次执行必须编译+运行成功（语法正确性）
- 所有结果必须 `>= 0`（非负性）
- 任一失败则拒绝保存

## 七、错误处理与回退

### 预扣费阶段（请求到达）

表达式运行失败 → 直接返回错误，请求被拒绝。

### 结算阶段（响应返回后）

表达式运行失败 → 回退链：
1. 使用 `relayInfo.FinalPreConsumedQuota`（实际预扣额度）
2. 若该值 ≤ 0，使用 `snapshot.EstimatedQuotaAfterGroup`（预估额度）
3. 日志中不记录档位信息（`result = nil`）

### 编译缓存

- 编译后的表达式程序按 SHA-256 缓存，最多 256 条
- 缓存溢出时全部清空重建
- 管理员更新表达式后主动调用 `InvalidateCache()` 清除缓存

---

## 八、与工具调用计费的配合

当阶梯计费与工具调用计费同时生效时，最终额度计算方式：

```
finalQuota = Round(tieredResult.ActualQuotaBeforeGroup × groupRatio + toolCallSurchargeQuota)
```

工具调用附加费（web_search、file_search、image_generation）独立计算后**叠加到**阶梯计费结果之上，不参与表达式运算。

## 九、可视化编辑器使用

### 管理后台路径

**系统设置 → 分组与模型定价设置 → 选择模型 → 切换为阶梯计费**

### 编辑器功能

1. **档位管理：** 添加/删除/排序价格档位
2. **条件编辑：** 可视化配置 `len`/`p`/`c` 的区间条件
3. **价格编辑：** 为每个档位配置各 token 维度的 $/1M 价格
4. **缓存模式选择：** 定时缓存（5m + 1h）或通用缓存
5. **请求规则：** 基于 header/param/时间的乘数规则（生成到表达式末尾）
6. **实时预览：** 查看生成的表达式字符串
7. **LLM 辅助：** 内置提示词帮助理解表达式语法

### 模型定价详情弹窗

在模型定价列表中，阶梯计费模型会显示 **"动态计费"** 标识，点击查看：
- 各档位的条件和价格明细（含货币转换）
- 请求规则乘数列表
- 原始表达式字符串

```bash
curl -X POST http://localhost:3000/v1/chat/completions \
  -H "Authorization: Bearer sk-user-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4",
```

```bash
  }'

# fast 模式请求 — 费用 ×3
curl -X POST http://localhost:3000/v1/chat/completions \

  -H "Content-Type: application/json" \
  -d '{

    "service_tier": "fast",
    "messages": [{"role": "user", "content": "hello"}]
  }'
```

### 10.3 查看模型定价信息

```bash
# 获取所有模型定价列表（包含 billing_mode 和 billing_expr）
curl http://localhost:3000/api/pricing \
  -H "Authorization: Bearer sk-user-xxx"
```

响应中阶梯计费模型会包含：
```json
{
  "model_name": "claude-sonnet-4",
  "billing_mode": "tiered_expr",
  "billing_expr": "len <= 200000 ? tier(\"standard\", ...) : tier(\"long_context\", ...)"
}
```

### 10.4 流式请求

阶梯计费对流式/非流式完全兼容，预扣费在请求开始时执行，结算在响应完成后执行：

```bash
curl -X POST http://localhost:3000/v1/chat/completions \
  -H "Authorization: Bearer sk-user-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4",
    "stream": true,
    "messages": [
      {"role": "user", "content": "写一篇关于人工智能的短文"}
    ],
    "max_tokens": 2048
  }'
```

### 10.5 消费日志查看

请求完成后，在管理后台 **日志 → 使用日志** 中，阶梯计费的日志 `other` 字段会包含：

```json
{
  "billing_mode": "tiered_expr",
  "expr_b64": "bGVuIDw9IDIwMDAwMCA/IHRpZXIoInN0YW5kYXJkIiwg...",
  "matched_tier": "standard"
}
```

前端会自动解析并展示动态计费详情，包括匹配档位、各维度价格明细。
