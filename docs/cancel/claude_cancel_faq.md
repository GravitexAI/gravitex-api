# 流式取消计费 FAQ — 为什么"点了 Stop 上游账单还是按完整 token 算"

> 用途:用于回复用户关于"流式取消后为什么仍按完整 token 计费"的疑问。
> 核心结论:**这是 Anthropic / AWS Bedrock 上游 API 的硬性约束,任何第三方网关都无法绕开。** 行业里专门给这个现象起了个名字叫 **"Cancellation Tax(取消税)"**。

---

## 一、一句话结论

> 客户端点 **Stop / Cancel** 只是停止了前端渲染,**上游模型(Anthropic / AWS Bedrock)在大多数配置下会继续生成完整内容,并按完整 token 计费**。这跟用的是哪家网关无关,是上游 API 设计本身就不支持"取消即不计费"。

---

## 二、为什么会这样 — 三种厂商的真实行为对比

| 上游厂商 | 是否有 server-side cancel 机制 | 客户端 abort 后的实际计费行为 |
|---|---|---|
| **OpenAI**(直连) | 部分支持(只是"尽量") | 官方答复:断开连接会停止生成,但**仍会有 2~3 个传输中的 token 要算钱**;如果连接没被真正关闭,生成会"hang around"继续扣 |
| **Anthropic**(官方 SDK / Claude Code) | **没有** server-side cancel primitive | 客户端 abort 只断 socket,**上游模型继续生成、继续计费**,Anthropic 自家 SDK 都会"静默吞掉 abort" |
| **AWS Bedrock** | **没有** | AWS 继续按完整 input + output token 计费,跟客户端是否还在听完全无关 |

**结论:** 即便是行业里 cancel 处理得**最好**的 OpenAI,也只是做到了"还有 2~3 个 token 在路上要算钱"。Anthropic 和 AWS Bedrock 连这点机制都没有。

---

## 三、权威证据

### 证据 1:AWS Bedrock 官方文档 — 计费基数是"模型生成的"token

**链接:** https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html

**原文:**

> The `OutputTokenCount` metric in CloudWatch represents the number of tokens **generated by the model** in response to a request.
>
> At the end of a request, the total tokens consumed are calculated as: `InputTokenCount + CacheWriteInputTokens + (OutputTokenCount × burndown rate)`.
>
> For Anthropic Claude models version 3.7 and later, the burndown rate for output tokens is **5×**.

**这条意味着:**
- AWS 官方明确说计费基数是"模型 generated 的"token,**不是"客户端 received 的"**。
- 文档全文**没有任何一句话**提到"客户端断开 / 取消会减少账单"。
- Claude 3.7+ 在 Bedrock 上每个输出 token 还要按 **5×** burndown 算 quota,所以**取消反而损失更大**。

### 证据 2:Anthropic 官方仓库 — 自家工程师都承认 cancel 拦不住上游

#### 2.1 anthropic-sdk-typescript #867
**链接:** https://github.com/anthropics/anthropic-sdk-typescript/issues/867

社区在向 Anthropic 提需求"加一个 streaming idle timeout",因为**断开客户端连接不能保证上游停止生成**,会一直挂着继续产生费用。

#### 2.2 anthropics/claude-code #54288
**链接:** https://github.com/anthropics/claude-code/issues/54288

**标题:**
> Extended thinking burns unlimited tokens on 'continue' with large context — no output, no timeout, requires SIGKILL

issue 里有用户报告:**一次取消未及时生效,烧掉了月度 token 预算的 ~50%**,**输出全部没看到也照样计费**。这是 Anthropic 自家仓库,他们的工程师都在那条 issue 下面。

#### 2.3 anthropics/claude-code #38905
**链接:** https://github.com/anthropics/claude-code/issues/38905

> Silent stream abort causes Claude to stop mid-task without error

Anthropic 官方 SDK 会"静默吞掉 abort",**客户端能拿到的只是断开前到达的部分,但 token 还是按上游已生成的算**。

### 证据 3:行业头部 AI 网关 LiteLLM(47k stars)亲身实测 — 做不到

#### 3.1 LiteLLM #14457 ——作者亲口承认试过了
**链接:** https://github.com/BerriAI/litellm/issues/14457

**标题:**
> [Bug]: Usage data lost when **streaming responses are terminated early by client disconnect**

**作者 jasonpnnl 评论(2025-09-26):**
> These are serious issues since it's essentially an **infinite money glitch**. Users can run long running sessions and then cancel it before completion which causes it to not be tracked in usage logs, or quotas/budgets. **I attempted to fix this issue, and while I found a way to track the usage on a streaming response that was cancelled up to the point that it was cancelled, could not figure out how to get it to actually cancel the upstream LLM call.**

> 翻译:我尝试修过这个 bug。我能追踪到"取消那一刻为止"的用量,**但我试遍了所有方法都没法让上游 LLM 真的停下来**。

#### 3.2 LiteLLM #17364 ——另一位开发者提 PR 尝试也失败
**链接:** https://github.com/BerriAI/litellm/issues/17364

**开发者 vtsigelnikov 实测描述:**
> I made a pull request with a possible solution, but I ran into the problem of disconnecting from the LLM provider, i.e. the disconnection from the client is correctly tracked and the received tokens are saved in the spend log, **but the LLM provider's response is completely tracked despite the fact that I break the iterator and close the stream.**

**结局:** 这个 feature 最终被 LiteLLM 维护者标记为 `not_planned` 关闭 —— 也就是说**做不到,不打算做了**。

#### 3.3 LiteLLM PR #26719 ——最终合并的修复方向是"补扣费",不是"少扣费"
**链接:** https://github.com/BerriAI/litellm/pull/26719

**标题:**
> fix(passthrough): track spend for interrupted Bedrock streams

**PR 描述:**
> When a client disconnects mid-stream from a Bedrock pass-through endpoint (e.g. user terminates a Claude Code session) ... every captured per-chunk usage value was silently dropped — **undercounting spend**.

**注意修的方向:** LiteLLM 2026 年最终合并的修复,是把客户端 cancel 后**没扣到的钱补扣回来**(因为上游 Bedrock 那边已经按完整 token 扣过他们了)。**反向证明:Bedrock 上游就是按完整 token 收钱的。**

### 证据 4:OpenAI 官方开发者论坛 — 行业里处理最好的也只能做到这样

**链接:** https://community.openai.com/t/api-billing-for-streaming-if-i-close-connection-midway/624323

**用户问题(跟你们用户问的一模一样):**
> If I am using the streaming feature and I close the connection midway, will I be charged only by the tokens that I have consumed through the stream till now or will it be charged by the entire number of tokens that will be generated in the completion?

**OpenAI 论坛官方答复:**
> Yes, sort of. Terminating the connection will end the generation. That said, **there might still be 2 or 3 tokens in transit that you will be charged for.**
>
> PS: Be advised that you have to make sure the connection to openai is actually cancelled/closed. **Sometimes they just hang around if you're not careful.**

**这条的价值:** OpenAI 是行业里这件事处理得**最好**的厂商,极限也只是"还有 2~3 个 token 要算钱"。**Anthropic / AWS Bedrock 连这个 server-side abort 机制都没做。**

---

### 证据 5:Stack Overflow 同问题 Accepted Answer

**链接:** https://stackoverflow.com/questions/78501938/how-to-stop-generating-response-in-openai-library-for-python

> **You are charged for all the tokens the API generates, even if you don't process them.** So, breaking the loop early stops you from getting more output tokens as you're streaming **but there would be some output tokens that'll be generated but didn't make it to your end, it doesn't stop you from being charged for those tokens.**

### 证据 6:行业通用术语 "Cancellation Tax(取消税)"

**链接:** https://tianpan.co/blog/2026-04-23-cancellation-tax-streaming-abort-billing

行业里专门给这个现象起了名字叫 **Cancellation Tax(取消税)**,意思就是"用户以为按了 Stop 就不花钱,但其实账单照算"。文章里几段最直白的话:

> Your stop button is a lie. When a user clicks it, your UI stops rendering tokens; **your provider, in most configurations, keeps generating them**. The bytes never reach a browser, but they reach your invoice.

> There are three places where a cancellation could happen: in the client, in the proxy, and in the inference engine. **Only the third one actually saves money. The first two are theater.**

> OpenAI's Responses API, as of its current shape, only supports `responses.cancel` for background responses — **synchronous streaming responses have no cancel endpoint at all; you disconnect the socket and hope.** ... **Anthropic's SSE messages lack timeouts, heartbeats, or a server-side cancel primitive**.

> The practical result: when you paste `abortController.abort()` into your frontend, you can measure its effect in two ways. **Tail latency on the client drops to zero immediately. Your provider bill, measured two weeks later, does not move.**

## 四、整合版

> 关于流式取消的计费,这其实是整个 AI API 行业的通用行为。简单说:**客户端点 Stop 只是停止了前端渲染,上游模型(Anthropic / AWS Bedrock)在大多数配置下会继续生成完整内容并按完整 token 计费。**
>
> 几个权威依据:
>
> 1. **AWS Bedrock 官方文档** 明确说明计费基数是 `OutputTokenCount`(模型生成的 token),不是客户端接收的 token,Claude 3.7+ 在 Bedrock 上还要按 5× burndown 算 quota。
> https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html
>
> 2. **行业头部 AI 网关 LiteLLM(47k stars)的 issue #14457** —— 标题就是 "Usage data lost when streaming responses are terminated early by client disconnect"。作者亲口在评论里说:"I attempted to fix this issue ... **could not figure out how to get it to actually cancel the upstream LLM call**"(他试过了,无法让上游真的取消)。
> https://github.com/BerriAI/litellm/issues/14457
>
> 3. **LiteLLM issue #17364** —— 另一个开发者提交 PR 尝试实现"客户端断开时取消上游",实测结论:"the LLM provider's response is completely tracked despite the fact that I break the iterator and close the stream"(我把客户端 iterator break、把流 close 掉,上游响应仍然被完整计费)。该 feature 最后被 LiteLLM 维护者标记为 `not_planned` 关闭。
> https://github.com/BerriAI/litellm/issues/17364
>
> 4. **LiteLLM PR #26719(2026-04-30 已合并)** —— LiteLLM 团队最终合并的修复方向是"**把客户端 cancel 后漏扣的费用补扣回来**",原因是"AWS Bedrock 那边已经按完整 token 扣过钱了,网关层不扣就亏损"。这反向证明 Bedrock 上游就是按完整 token 收钱的。
> https://github.com/BerriAI/litellm/pull/26719
>
> 5. **Anthropic 官方仓库 claude-code issue #54288** —— 用户取消后 token 仍持续燃烧,他们自己也承认 "requires SIGKILL"。
> https://github.com/anthropics/claude-code/issues/54288
>
> 6. **OpenAI 官方开发者论坛**对类似问题的答复(OpenAI 是这件事处理得最好的厂商):"Terminating the connection will end the generation. That said, **there might still be 2 or 3 tokens in transit that you will be charged for**."
> https://community.openai.com/t/api-billing-for-streaming-if-i-close-connection-midway/624323
>
> 7. 业内对这个现象有专门术语叫 **"Cancellation Tax(取消税)"**:"Your stop button is a lie ... only [cancellation in the inference engine] actually saves money. The first two are theater."
> https://tianpan.co/blog/2026-04-23-cancellation-tax-streaming-abort-billing
>
> 综上:
> - **OpenAI 直连**:有一点点 server-side abort,所以表面"基本可以取消",但官方也明说还有 2~3 个 token 要算钱;
> - **Anthropic / AWS Bedrock**:**没有 server-side cancel 机制**,这是上游 API 的设计选择,任何走 Bedrock 的网关都改不了;
> - 如果有别家产品"取消后用户付费更少",那只可能是**他们自己在内部把上游账单和用户账单的差额吃掉了**,不是 AWS / Anthropic 那边真的少扣了。
>
> 如果您找到了能让 Anthropic / Bedrock 上游真的"取消即不计费"的具体产品和对账证据,非常欢迎告诉我们,我们也很想了解。

## 五、关键术语速查

- **Cancellation Tax(取消税)**:用户点 Stop 后,虽然前端不再渲染 token,但上游模型仍在生成、仍按完整 token 计费的现象。
- **Server-side cancel primitive**:由上游 API 提供的、能真正终止模型生成的取消机制。**目前 Anthropic 和 AWS Bedrock 都没有提供**。
- **Burndown rate**:AWS Bedrock 把每个输出 token 折算成 quota 配额的倍率。Claude 3.7+ 是 **5×**。
- **Infinite money glitch**:LiteLLM 作者对这个 bug 的形容 —— 用户通过反复"启动长流式 → 取消"可以让网关追踪不到用量,但上游照样收钱。
