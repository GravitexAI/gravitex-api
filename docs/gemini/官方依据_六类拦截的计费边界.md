# 官方依据：Gemini 生图六类拦截的计费边界

> 用途：回应客户「六类失败应全额免除」的主张，逐类给出 Google 官方文档依据
> 日期：2026-09-22
> 配套：`测试证据_生图拦截计费_20260921.md`（实测数据）、`客户回复_生图拦截计费口径说明.md`（对外稿）

---

## 〇、一句话立场

**我们的计费边界，就是 Google 的计费边界 —— 不是我们自己划的。**

- Google 明示**不收**的部分（被拦截的图片输出）→ 我们**不收**
- Google **照常收**的部分（输入 token、文本与思考输出 token）→ 我们**照收**

下面每一条都给出官方出处。

---

## 一、四条总则（官方原文）

### 总则 1：只有 HTTP 200 才计费

> **"You're charged only for requests that return a 200 response code. Requests returning any other response codes, such as 4xx and 5xx codes, aren't charged for the input or output."**

出处：[Vertex AI / Agent Platform 生成式 AI 定价页](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing)，页首计费总则

同页另有：

> "If your request fails with a 400 or 500 error, you won't be charged for the tokens used."

### 总则 2：被拦截的图片不收费

> **"Your current safety filter threshold filtered out 2 generated images. `You will not be charged for blocked images.` Try rephrasing the prompt."**

出处：[Responsible AI and usage guidelines for Imagen](https://cloud.google.com/vertex-ai/generative-ai/docs/image/responsible-ai-imagen)，`raiFilteredReason` 响应示例

同一句话也出现在 Gemini 生图被拦时的 `finishMessage` 中。以下为我方 2026-09-21 在真实 Vertex 上游实测捕获的原文：

> "Unable to show the generated image. The image was filtered out because it violated Vertex AI's usage guidelines. **You will not be charged for blocked images.** Try rephrasing the prompt. If you think this was an error, send feedback. **Support code: 14952152.**"

### 总则 3：思考（reasoning）token 属于**收费**的输出档

Vertex 定价页对 Gemini 3 Pro Image（Nano Banana Pro）的分档：

| 计费项 | 官方表述 | 单价（≤200K） |
|---|---|---|
| Input (text, image) | 输入 | $2.00 / 1M |
| **Text output (response and reasoning)** | **响应与推理** | **$12.00 / 1M** |
| Image Output | 图片输出 | $120.00 / 1M |

**关键**：Google 把 reasoning 明确写进了 `Text output` 这一档的名称里 —— **"response **and reasoning**"**。思考 token 是收费的，且按文本价 $12/1M，不是图片价 $120/1M。

出处：同定价页 Gemini 3 系列表格。图片 token 折算见同页脚注：

> "Gemini 3 Pro Image charges 560 tokens per input image, with output image costs scaling by resolution: 1120 tokens ($0.134) for 1K and 2K (roughly 1MP and 4MP), and 2000 tokens ($0.24) for 4K (roughly 16MP)."

### 总则 4：拦截有「输入侧」和「输出侧」两层，响应结构不同

出处：[Process blocked responses](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/process-blocked-responses)

> **输入被拦**：
> - "The `promptFeedback` field is populated."
> - "The `candidates` field **isn't set**."
>
> **输出被拦**：
> - "The `promptFeedback` field **isn't set**."
> - "The `candidates` field **is set**" ，其中 "The `content` field **isn't set**"，"The `finishReason` field is set"

出处：[Gemini image generation and responsible AI](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/gemini-image-responsible-ai)

> - "**Model refusal**: If a prompt is potentially unsafe, the model might refuse to process the request... The `FinishReason` is **`STOP`**."
> - "If the **prompt** is identified as potentially harmful by a safety filter, the API returns **`BlockedReason` in `PromptFeedback`**."
> - "If the **response** is identified as potentially harmful by a safety filter, the API response includes a **`FinishReason` of `IMAGE_SAFETY`, `IMAGE_PROHIBITED_CONTENT`, or similar**."

## 二、逐类对照

对照客户提供的六类分布表。**六类的图片输出费用我方一律不收**；差别只在于「这一类本来有没有图片费可免」，以及输入与思考 token 是否照收。

### ① `IMAGE_PROHIBITED_CONTENT`（输出侧）

| 项 | 内容 |
|---|---|
| 官方定义 | 候选侧 `FinishReason`，图片生成后被责任 AI 策略过滤 |
| HTTP 状态 | **200**（总则 4：candidates 存在、content 为空） |
| Google 是否收图片费 | **否**（总则 2） |
| Google 是否收输入/思考 | **是**（总则 1 + 总则 3：200 响应，reasoning 在收费档） |
| **我方计费** | 不收图片费；按上游实际用量收输入 + 思考 |

### ② `IMAGE_SAFETY`（输出侧）

同 ①。官方 `BlockReason` 枚举对该值的描述为：

> `IMAGE_SAFETY` — "Candidates blocked due to unsafe image generation content."

出处：[GenerateContent API 参考](https://ai.google.dev/api/generate-content)

⚠️ **同名不同层**：`IMAGE_SAFETY` 既可能出现在输入侧 `BlockReason`，也可能出现在输出侧 `FinishReason`。判别方法是看 `candidates` 是否存在（总则 4）。客户表中第 ⑤ 行的「prompt 级 IMAGE_SAFETY」即为输入侧。

### ③ `NO_IMAGE`

| 项 | 内容 |
|---|---|
| 官方定义 | 候选侧 `FinishReason`，模型未产出图片 |
| 性质 | **不是策略拦截** —— 模型没有生成图片，而非生成后被拦 |
| 是否有图片费可免 | **没有**。既然未产生图片输出，就不存在图片 token，也就没有图片费可免 |
| Google 是否收输入/思考 | **是**。模型已完成思考过程，该算力实际发生 |
| **我方计费** | 仅输入 + 思考 |

> 客户表中该行自注为「无 finishMessage，thoughts+text token 被计费」，与官方口径及我方口径一致。

### ④ prompt 级 `PROHIBITED_CONTENT` / `OTHER`

| 项 | 内容 |
|---|---|
| 官方定义 | 输入侧 `BlockReason`。`PROHIBITED_CONTENT` 为不可配置过滤器 |
| 官方原文 | "The prompt was blocked because it was flagged for containing prohibited contents, usually CSAM." |
| 响应结构 | `promptFeedback` 有值，`candidates` **不存在**（总则 4） |
| 官方示例报文 | `{"promptFeedback":{"blockReason":"PROHIBITED_CONTENT"},"usageMetadata":{"promptTokenCount":7,"totalTokenCount":7}}` |
| 是否有图片费可免 | **没有**。请求在进入生成前即被拦，无任何输出 |
| **我方计费** | 仅输入 token。该类单笔通常低于 $0.001 |

出处：[Safety and content filters](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/configure-safety-filters)

> 注意官方示例报文中 `usageMetadata.promptTokenCount` 有值 —— Google 对输入侧拦截仍统计并计费输入 token。

### ⑤ 输出侧 `PROHIBITED_CONTENT` / prompt 级 `IMAGE_SAFETY`

该行为混合类别，需拆开：

- **输出侧 `PROHIBITED_CONTENT`** → 同 ①，不收图片费
- **prompt 级 `IMAGE_SAFETY`** → 同 ④，输入侧拦截，本就无图片费

### ⑥ `IMAGE_RECITATION`

| 项 | 内容 |
|---|---|
| 官方定义 | 候选侧 `FinishReason`，图片生成后因复现受版权保护内容被拦 |
| 处理 | 同 ①，不收图片费，按实际用量收输入 + 思考 |

## 三、汇总表

| 客户分类 | 拦截层 | HTTP | 有图片费可免吗 | 我方收图片费 | 我方收输入+思考 |
|---|---|---|---|---|---|
| ① IMAGE_PROHIBITED_CONTENT | 输出侧 | 200 | 有 → **已免** | ❌ | ✅ |
| ② IMAGE_SAFETY | 输出侧 | 200 | 有 → **已免** | ❌ | ✅ |
| ③ NO_IMAGE | 非拦截 | 200 | **本就没有** | ❌ | ✅ |
| ④ prompt 级 PROHIBITED_CONTENT / OTHER | 输入侧 | 200 | **本就没有** | ❌ | ✅（仅输入） |
| ⑤ 输出侧 PROHIBITED_CONTENT / prompt 级 IMAGE_SAFETY | 混合 | 200 | 前者有→已免；后者本就没有 | ❌ | ✅ |
| ⑥ IMAGE_RECITATION | 输出侧 | 200 | 有 → **已免** | ❌ | ✅ |

**六类的图片输出费用，我方一律不收。** 差异仅在于 ③④ 以及 ⑤ 的一半本身就不产生图片输出，不存在「免」这个动作。

## 四、最强的一条论据：Google 根本没给我们计费依据

这一点比任何条款都直接。

我方 2026-09-21 在真实 Vertex 上游实测，`IMAGE_SAFETY` 被拦时返回的完整 `usageMetadata`：

```json
{
  "promptTokenCount": 27,
  "totalTokenCount": 343,
  "trafficType": "ON_DEMAND",
  "promptTokensDetails": [{"modality": "TEXT", "tokenCount": 27}],
  "thoughtsTokenCount": 316
}
```

**`candidatesTokenCount` 与 `candidatesTokensDetails` 两个字段整体不存在。**

图片输出的计费依据是 `candidatesTokensDetails` 中的 IMAGE modality token 数。Google 在拦截时**根本不上报这个字段**，因此：

> **不是「我们选择不收」，而是「计费依据从未产生」。**

文生图、图生图两种形态实测结果一致。

生产数据可交叉印证：2026-07 ~ 09 共 **1,956 笔**被拦请求，全部以「零图片 token」形态入账，合计收费 **$17.59**（平均每笔约 $0.009，全部为输入 + 思考）。若 Google 会在拦截时上报图片 token，这些请求就会落入「有图片 token」档、单价 $0.13 以上，不可能出现在这个区间。

## 五、可能的追问与应答

**问：那为什么我们统计到这些失败请求有 $0.13 左右的费用？**

答：请提供对应的 request_id。按我方逐笔记录，输出侧拦截的单笔费用区间为 $0.0009 ~ $0.018（仅输入 + 思考）。$0.13 是**成功交付图片**的典型价格（1K/2K 图 1120 tokens × $120/1M = $0.134）。两者相差约 30 倍，逐笔核对即可区分。

**问：思考 token 为什么要收费？图都没出来。**

答：Google 定价页把该档明确命名为 "Text output (**response and reasoning**)"，单价 $12.00 / 1M。模型的推理算力实际发生，Google 向我们照常计费。我方按同一口径向您计费，未加成。

**问：请求失败了为什么还要付钱？**

答：需区分两种「失败」。上游返回 **4xx / 5xx** 的请求，按总则 1 一律零计费 —— 例如贵司 2026-08 的 `gemini-3-pro-image` 有 **137,767 笔**（占 34.6%）属于此类，**全部未计费**。而安全策略拦截返回的是 **HTTP 200**，Google 对其中已实际产生的算力照常收费。

**问：能不能连输入和思考也一起免？**

答：这属于商务让步，不属于计费口径问题。计费口径上这部分是 Google 实收的成本。
