## 一、结论摘要

| 待验证的说法 | 结论 | 依据 |
|---|---|---|
| 被拦截的图片按整张收费 | ❌ **不成立** | 上游对被拦图**不上报** `candidatesTokenCount`，我方无从计费。实测 2 例 + 生产 1,956 例 |
| 思考（reasoning）token 按图片单价计费 | ❌ **不成立** | 思考始终走文本档。线上倍率与阶梯表达式均与官方一致 |

| **纯文本响应按图片单价计费** | ✅ **成立** | 已修复。7–9 月净多收 **$42.81** / 5,370 笔 |

## 四、关键事实：上游对被拦图片不上报 token

用例 #7 的上游原始 `usageMetadata`（完整，无删减）：

```json
{
  "promptTokenCount": 27,
  "totalTokenCount": 343,
  "trafficType": "ON_DEMAND",
  "promptTokensDetails": [{"modality": "TEXT", "tokenCount": 27}],
  "thoughtsTokenCount": 316
}
```

**`candidatesTokenCount` 与 `candidatesTokensDetails` 两个字段整体缺失。**

同一响应的 `finishMessage`：

> Unable to show the generated image. The image was filtered out because it violated Vertex AI's usage guidelines. **You will not be charged for blocked images.** Try rephrasing the prompt. If you think this was an error, send feedback. **Support code: 14952152.**

用例 #8（图生图）行为完全相同。**即：无论文生图还是图生图，Vertex 在图片被拦时都不上报图片 token，因此网关在修复前也没有、也不可能按图片档计费。**

## 六、唯一确认成立的缺陷：纯文本响应误按图片计费

### 机制

旧代码在原生端点判断输出类型时，当上游未给出 IMAGE 明细则回退到「模型名是否含 `image`」。图片模型返回纯文本时，整段文本被划入图片输出。

生产实例（`gemini-3.1-flash-image-preview`）：

```
上游:  "candidatesTokensDetails": [{"modality":"TEXT","tokenCount":518}]
       "thoughtsTokenCount": 0
网关:  image_output_tokens = 518,  text_output_tokens = 0
结果:  518 个文本 token 按 $60/M 计费，应为 $3/M
```

注意 `thoughtsTokenCount = 0` —— **与思考 token 无关**，误判的是模型回复的正文。

### 金额（2026-07 ~ 09）

筛选条件：`image_output_tokens` 在 1–746 之间（低于最小真实图片档位 747）且 `text_output_tokens = 0`。

## 七、可复现的打桩方法

真实触发安全过滤不稳定（同一 prompt 时灵时不灵，且输出侧过滤不受 `BLOCK_NONE` 控制），回归验证请用打桩：

```bash
python3 scripts/gemini-block-repro/mock_vertex.py    # 监听 :8799
```

建 Gemini 渠道指向它，用模型重定向 `{"gemini-3-pro-image": "<场景名>"}` 切换场景。

| 场景名 | 构造的上游响应 |
|---|---|
| `block-image-prohibited` | finishReason=IMAGE_PROHIBITED_CONTENT + IMAGE 1120 tok |
| `block-image-safety` | finishReason=IMAGE_SAFETY + IMAGE 1120 tok |
| `block-no-image` | finishReason=NO_IMAGE，无候选 token，思考 5300 |
| `block-prompt-prohibited` / `-other` / `-image-safety` | 仅 promptFeedback.blockReason |
| `block-image-recitation` | finishReason=IMAGE_RECITATION + IMAGE 1120 tok |
| `refuse-text-only-image` | STOP + TEXT 48 tok（复现第六节缺陷） |
| `ok-image` | STOP + 真实 inlineData（对照组，金额必须不变） |

> 打桩场景刻意让被拦响应**带上** IMAGE token —— 真实 Vertex 不这样报，但这样才能验证护栏本身有效（万一上游日后改行为）。加 `?alt=sse` 走流式，桩会把图片和 usageMetadata 分两包发，用于验证「末包无图片数据」不会被误判。

**zsh 注意**：循环里必须写 `"${s}:generateContent"`，写成 `"$s:generateContent"` 会被当作参数修饰符吞掉。

## 八、复核 SQL（可直接复制）

```sql
-- ① 真实被拦请求的规模与金额
SELECT formatDateTime(toDateTime(created_at),'%Y-%m') AS ym,
       count() AS cnt, round(sum(quota)/500000,2) AS usd
FROM logs
WHERE model_name LIKE 'gemini-%image%'
  AND quota > 0
  AND JSONExtractInt(other,'image_output_tokens') = 0
  AND JSONExtractInt(other,'reasoning_tokens') > 0
GROUP BY ym ORDER BY ym;

-- ② 纯文本被误按图片计费的净多收
SELECT username, count() AS cnt,
  round(sum(JSONExtractInt(other,'image_output_tokens')
        * (JSONExtractFloat(other,'output_image_price')
           - JSONExtractFloat(other,'model_ratio')*JSONExtractFloat(other,'completion_ratio')*2)
        /1000000 * if(JSONExtractFloat(other,'group_ratio')>0,JSONExtractFloat(other,'group_ratio'),1)),2) AS overcharge
FROM logs
WHERE model_name LIKE 'gemini-%image%'
  AND JSONExtractInt(other,'image_output_tokens') BETWEEN 1 AND 746
  AND JSONExtractInt(other,'text_output_tokens') = 0
GROUP BY username ORDER BY overcharge DESC;

-- ③ 修复上线后的护栏生效情况（admin_info 是嵌套的，必须分两个参数）
SELECT formatDateTime(toDateTime(created_at),'%Y-%m-%d') AS d,
       count() AS cnt,
       sum(JSONExtractInt(other,'admin_info','blocked_image_tokens')) AS waived_tokens
FROM logs
WHERE model_name LIKE 'gemini-%image%'
  AND JSONExtractInt(other,'admin_info','blocked_image_tokens') > 0
GROUP BY d ORDER BY d;

-- ④ 按 request_id 出逐笔拆解（客户提供清单时用）
SELECT request_id, model_name, prompt_tokens, completion_tokens,
       round(quota/500000,6) AS usd,
       JSONExtractInt(other,'image_output_tokens') AS img_o,
       JSONExtractInt(other,'text_output_tokens')  AS txt_o,
       JSONExtractInt(other,'reasoning_tokens')    AS think,
       JSONExtractString(other,'admin_info','upstream_finish_reason') AS finish
FROM logs WHERE request_id IN (...);
```

> `blocked_image_tokens` 与 `upstream_finish_reason` 自 `33894c2bb` 起写入，此前的记录没有这两个字段。

## 九、修复内容与回归覆盖

修复要点：**图片输出 token 只在响应中确实包含图片数据时才计费**，不再依据模型名称推断。

覆盖入口：Gemini 原生 `:generateContent`、OpenAI 格式 `/v1/chat/completions`、流式（两个入口共用）、Responses 端点。`/v1/images/generations` 原本即正确退款。

回归测试 `relay_gemini_blocked_image_test.go`，13 个子用例：

- 4 种拦截类型 × 2 个入口 —— 被拦时 `img_o = 0` 且图片 token 从计费总量中剔除
- 正常出图 × 2 个入口 —— 金额不变
- 流式 × 2 —— 图片在前序包交付时不被误判为拦截
- 纯文本拒答 × 1 —— 按文本档而非图片档计费

流式的关键约束：末包只有 usageMetadata、没有图片数据，必须按**全流累计**的交付状态判定，只看末包会把正常出图误判成被拦。
