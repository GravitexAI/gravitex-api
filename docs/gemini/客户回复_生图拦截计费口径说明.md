## 一、结论

我们已对 2026-07 账期 Gemini 生图请求完成逐笔核查，结论如下：

1. **图片生成后被安全策略拦截的请求，我方不收取图片输出费用。** 这类请求仅收取上游实际产生的输入 token 与思考（reasoning）token，单笔约 **$0.004**。
2. **上游返回错误（403 / 429 / 404 等）的请求，我方零计费。**
3. 您提供的分析表中列示的单笔金额（$0.126 – $0.145）与我方计费口径不一致，我方对应场景的实际计费约为其 **1/30**。
4. 核查中我们**主动发现并确认了一处我方的计费缺陷**：当图片模型返回纯文本（而非图片）时，该段文本曾被误按图片单价计费。您 7 月账期受此影响的有 **1 笔**，涉及金额 **$0.05**。该缺陷已修复，详见第六节。
5. 7 月账期已按您的诉求完成减免，上述 $0.05 亦已包含在内，无需再作调整。本说明用于明确后续账期口径。

## 二、我们的计费口径

Gemini 3 Pro Image（Nano Banana Pro）按 Google Vertex AI 官方公布的 token 单价计费，分三档：

| 计费项 | 官方单价 | 说明 |
|---|---|---|
| 输入（文本 + 参考图） | $2.00 / 1M tokens | 参考图按 560 tokens/张折算 |
| 文本与思考输出 | $12.00 / 1M tokens | 含 reasoning / thinking tokens |
| **图片输出** | **$120.00 / 1M tokens** | 1K/2K 图 1120 tokens ≈ $0.134；4K 图 2000 tokens ≈ $0.24 |

**关键点：图片输出这一档，只有在图片实际交付给您时才会计费。**

Google 在被拦截的响应里会明确附带一句：

> *"You will not be charged for blocked images."*

我方计费与这一声明一致。

## 三、对应您表中的六类情况

| 您的分类 | 我方是否收取图片费 | 我方实际计费 |
|---|---|---|
| `IMAGE_PROHIBITED_CONTENT`（图已生成后被过滤） | **否** | 仅输入 + 思考 token |
| `IMAGE_SAFETY`（输出侧安全策略拦截） | **否** | 仅输入 + 思考 token |
| `NO_IMAGE`（模型思考后未出图） | **否**（本就无图片 token） | 仅输入 + 思考 token |
| prompt 级 `PROHIBITED_CONTENT` / `OTHER` | **否** | 仅输入 token（通常 < $0.001） |
| prompt 级 `IMAGE_SAFETY` | **否** | 同上 |
| `IMAGE_RECITATION`（版权复读拦截） | **否** | 仅输入 + 思考 token |

补充说明：**输入 token 与思考 token 会正常计费**。这部分是上游实际发生的算力消耗，Google 对我们照常收取，因此不在减免范围内。以一次典型拦截为例，输入 27 tokens + 思考 316 tokens，合计计费 **$0.0038**。

## 六、我们做的改进

为让这类问题今后可以自证、无需逐案人工核查，我们已上线两项改进：

1. **修复「纯文本响应误按图片计费」**（第一节第 4 点）。旧逻辑在判断输出类型时参考了模型名称，导致图片模型返回纯文本时被归类为图片输出。现已改为**按响应中是否真实包含图片数据**判断，与模型名称无关。
2. **计费护栏**：响应中未实际返回图片内容时，图片输出 token 一律不计费。无论上游用量统计如何上报，被拦截的图片都不会产生图片档费用。
3. **计费溯源**：每笔请求的上游 `finishReason` 与「被豁免的图片 token 数」已写入账单明细。后续如对某笔计费有疑问，我们可以直接给出该笔请求的上游返回状态与逐项计费拆解。

## 七、后续对账方式

如对某个账期的具体请求有异议，请提供**失败请求的 request_id 清单**，我们会返回逐笔的：

- 上游 `finishReason` / `blockReason`
- 输入 / 思考 / 图片输出 token 的实际拆分
- 每一档的单价与金额

这样可以精确到单笔核对，避免按类别估算产生偏差。
